# Wisp Pocket

**少解释背景，让 AI 接上你的工作。**

macOS 15+ · 桌面 AI 助手 · 开发中

[使用场景](#从当前工作开始) · [产品方向](#接下来) · [本地体验](#本地体验) · [工程设计](#实现背后的设计)

在浏览器、文档和聊天之间切换时，你已经知道事情的来龙去脉，却常常需要向 AI 重新解释一遍。

Wisp Pocket 希望减少这段重复劳动：从随手唤起的输入面板开始，让 Agent 按需读取交付的资料、查询已记录的近期活动，把你的请求放回正在进行的工作里。简单问题随时问，复杂任务可以在同一段对话中继续推进。

## 从当前工作开始

### 随时唤起，带上正在看的内容

按 **⌘ ⇧ Space** 呼出 Spotlight 式输入面板，直接提问；也可以通过文本选区或区域截图入口，把要处理的内容附在请求中，确认后提交。选区与截图快捷键可在 Settings 中配置。

> 选中一段文字，再说：「把这段改得更简洁，保留原来的语气。」

### 把资料拖给桌宠，接着聊

可以创建多只桌宠，分别设置名字、描述、角色提示和图片，再安排到任意 Workspace。首次使用准备一只可见伙伴及十几只隐藏库存；创建项目不再附赠伙伴。设置中的 Pets / Workspaces 支持重新安排、查看项目历史和召来伙伴；同一实际目录复用项目，各 Thread 的对话上下文独立。

桌宠接收文本、链接和本地文件路径：拖到角色新建对话，拖到对话区追加当前对话。文件不预读、不复制，由 Agent 按需读取当前内容；文件修改后读到新内容，移动或删除后明确失败。角色图片由前端导入并受管保存。桌宠和完整对话窗口共用 Thread 历史。

首次启动只显示角色，之后恢复各宠对话显隐；点击角色即可唤出回复框并直接输入，没有历史时也能开始新对话，再次点击可隐藏并保留草稿。最新气泡和当前建议紧凑排列在回复框上方；悬停对话区可统一滚动查看完整消息与建议，移出后仍可继续输入。角色支持拖动保存位置；右键菜单提供伙伴管理、对话选择、唤出新伙伴、大小调节和隐藏入口。macOS 跨应用拖放、焦点和透明窗口行为仍需按手工清单继续验收。

### 接上刚才的线索

通过 **Context History**，Agent 可以查询近期应用与窗口活动，按需读取记录详情、缩略图和原始截图，为「刚才看的内容」补充线索。

Context History 随应用运行持续采集，关闭窗口继续，退出应用停止。缺少辅助功能或屏幕录制权限时，Settings 显示真实采集失败原因；已有历史仍可读取。实机记录及待验边界见 [验收清单](docs/manual-qa.md)。

### 让一次收藏成为任务的起点

配置 Chrome Bookmarks 触发器后，将网页收藏到指定文件夹，就能把标题和链接交给 Agent，按预设提示词向明确指定的 Workspace 发起新对话任务。也支持通过 System Clock 在设定时间触发任务。

> 例如，为一个收藏夹配置：「总结新收藏的文章，列出值得继续阅读的问题。」

书签入口需要安装并连接配套 Chrome 扩展，目前仍在完善连接可靠性。

## 让任务继续推进

- **从问答到执行**：主 Agent 负责轻量问答、读取与协调；需要自主规划、多步执行或反复验证的复杂任务，以及全部文件创建/修改，交给 Codex CLI。可以新建或接续当前 Thread 已关联会话，重启后关联保留。应用保持运行时，关闭窗口不停止后端任务。
- **读取与委托**：文件与保存历史、网页搜索和正文抓取首轮可用，无需工具激活；委托经过 Wisp 本次或永久 Permission，Codex 使用你已有的登录、模型、配置与内部权限。Append Prompt 保留可复用提示模板。
- **保留宿主能力**：MCP 配置与 macOS / Automation 的通道、实现和启用设置保留；首版未接入 Codex，主 Agent 不直接调用。Context History 继续采集，Automation 默认关闭；现有流程专项验收见人工清单。
- **模型由你选择**：从常驻 menu bar 的“设置”打开独立 Electron 窗口，在“模型服务”配置 OpenAI-compatible / Anthropic 模型、API Key 和服务地址；显式保存后下次模型请求生效。分组侧栏直接进入桌面伙伴、Codex 执行、MCP 服务器、权限和工作区；Codex 页显示安装/登录/启动状态并支持重新检查，MCP 保存只确认配置持久化。外观、快捷键、Host、触发器和 Append Prompt 继续从输入面板进入原生设置。

## 关于上下文与数据

初始上下文来自你提交的内容；历史活动随应用运行采集，实时宿主工具尚未迁入 Codex。历史查询和文件读取首轮可用且免确认，文件读取允许任意本地路径；Codex 工作目录来自所属 Workspace，目录不等于沙箱，其内部权限由用户 CLI 配置决定。项目根 AGENTS.md 每轮开始读取一次，下一轮使用最新内容。完整对话窗口展示所有项目的历史，项目分组不合并不同对话的模型上下文。Codex 委托继续权限策略，可本次授权或按完整工具名称记住决定，永久决定对所有桌宠生效。

Turn 中断只隔离旧执行结果，不保证 Codex 子进程停止，已完成文件修改保留；真实终止机制属于后续工作。

对话、附件、配置、Codex 会话关联与采集的活动记录保存在本机。模型请求及其中的上下文会发送至你配置的模型服务；网页搜索使用 Tavily，正文抓取会访问目标网站。

## 接下来

以下为后续规划：

- **扩展执行接入与终止**：设计 Wisp MCP、macOS、Automation 向 Codex 的能力出口，以及统一 Tool 真实停止、退出确认和收尾。

- **可积累的个人记忆**：将稳定偏好、任务进展与历史对话分开管理，按当前问题和近期线索召回、更新，让历史决策逐步成为可复用的协作背景。
- **从重复任务归纳流程**：在现有录制、保存和重跑能力之上，探索由 Agent 归纳处理流程，并在失败后辅助修正；完整自主修复尚未实现。

## 本地体验

需要 **macOS 15+、完整 Xcode（Swift 6）与 pnpm 10**；推荐使用 **Node.js 24**。

```bash
pnpm install
bash ./scripts/swiftw run HandAgentDesktop
```

启动后，在 **Settings** 中配置主 Agent 模型服务与 API Key，再按 **⌘ ⇧ Space** 发起第一个请求。复杂任务与写文件还需要已安装并登录的 **Codex CLI**；在“Codex 执行”检查状态，Wisp 不自动安装或登录。截图、屏幕读取与系统操作需要对应的 macOS 权限；图片输入需要支持多模态的模型 API。

网页搜索需要在启动环境中设置 `TAVILY_API_KEY`。启动排障与打包说明从 [开发文档](docs/docs.md) 进入，提示模板与 MCP 配置见 [示例](examples/examples.md)。

## 实现背后的设计

技术栈：**Swift / SwiftUI · TypeScript · React · Electron · Node.js · SQLite**。

| 工程问题 | 当前设计 |
| --- | --- |
| 上下文体积与相关性 | 主动附件与环境读取分开；历史查询提供活动索引、详情、缩略图和原图，供 Agent 按需逐层读取。 |
| 原生交互与持续任务 | Swift 负责快捷键、输入面板和系统能力；Electron 承载常驻界面并管理本地服务；React 展示对话，独立的 Agent Runtime 驱动执行。 |
| 跨进程状态一致性 | 核心层统一拥有 Thread / Turn 生命周期、输入队列与中断；SQLite 追加保存历史，输入与完成状态在持久化后确认，保存失败会暂停后续推进。 |
| 工具扩展与权限控制 | 核心层通过接口使用模型、存储和工具；主 Agent 直接读取并通过 Wisp Permission 委托 Codex；Thread 验证会话归属，Codex 使用 Workspace 工作目录与自身权限。 |

架构与模块入口见 [handAgent.md](handAgent.md)，统一术语见 [CONTEXT-MAP.md](CONTEXT-MAP.md)。

开发验证：`bash ./scripts/test.sh`、`bash ./scripts/swiftw test`、`bash ./scripts/swiftw build`。自动检查覆盖核心运行、协议与 UI 行为；系统权限、焦点和真实模型仍按 [验收清单](docs/manual-qa.md) 实测。
