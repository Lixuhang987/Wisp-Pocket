# pet-dialogue

一次性设计原型：比较“角色旁口袋”“横向资料长桌”“侧边对话手册”三种工作方式。需求、当前能力与未验证假设见[任务书](../../../../../../docs/design/pet-dialogue/brief.md)；本文只维护本目录的运行和验证边界。

## 直接子节点

- [index.html](./index.html)：UI 原型入口，`?variant=A/B/C` 切换方向。
- `app.js`：内存场景、三种布局与模拟交互；不连接生产 Thread 或工具。
- `styles.css`：桌面场景几何与布局；直接导入共享生成主题。
- [assets/assets.md](./assets/assets.md)：本次复用的角色、裁图来源、hash 与表现限制。
- [logic.html](./logic.html)：独立状态模型，用于检查 UI 原型之外的状态归属。
- `native-probe.cjs`、`native-probe.html`：原生 Electron 实验；结果与运行范围由设计研究记录维护，UI 页面不自动运行。

## 运行与比较

在仓库根目录执行 `pnpm prototype:pet`，打开 `http://127.0.0.1:4179/electron-shell/src/activity-window/prototypes/pet-dialogue/?variant=A`。底部左右按钮与键盘方向键切换方向；输入框、选择框和中文输入期间保留原按键用途。刷新会重置内存，URL 保留方向。

| 方向 | 不同的主要动作 | 阅读与导航结构 |
| --- | --- | --- |
| A 口袋对话 | 直接点桌宠，在它附近交付或回复 | 短气泡为常态，全文和对话历史分别显式展开 |
| B 桌面长桌 | 在资料区选择接收宠，再交付 | 资料、负责宠的工作、追问并列；公共台面只有示例资料 |
| C 对话手册 | 由桌宠进入稳定阅读面 | 左侧该宠历史，右侧连续对话和决定；宠物仍留在桌面 |

A 在 1440×900 视口使用约 326px 的工作态面板，展开长文约 375px，仅用于结构比较；这不替代任务书中的约 210px 常态设计，紧凑常态仍需按该方案另行验证。

所有方向共用角色、活动草案与状态；“全部同屏 / 单个位置”是独立显示方式。Miku 与小八都可从名字入口切换，后台工作不会因显示方式切换而取消。

## 可交互范围

- 点选桌宠、首次文字输入、普通回复、跟进排队与停止当前运行。
- 拖拽桌面的活动 PDF；真实浏览器 DataTransfer drop 与“交给当前桌宠”按钮走同一交付动作。
- 宠物本体接收会新建该宠对话，面板接收追加原对话；松手自动接收、读取示例资料并给建议，执行另等普通消息或建议动作。
- 每宠有独立历史、草稿、当前对话选择和历史筛选；切宠恢复它自己的搜索词与工作区筛选。新对话及本体 drop 使用档案默认工作区（本场景三只均为“读书交换日”），筛选不改变投递目标；面板 drop 继续使用原对话的工作区。
- 人设和表达设定保存后只用于新对话；已有对话保留开始时的提示快照。
- A/B 可展开全文与前文；C 提供可滚动完整对话；主动隐藏后继续保留运行和草稿。
- 八千代的建议可交接摘录给 Miku，Miku 的成稿可交给小八确认保存。交接创建目标宠的新对话，不移动原记录。
- 保存显示准确目标与正文预览；一次请求只接受一次回执，成果可在页面内打开预览。拒绝保存后继续处理该对话的排队消息；Stop 保持暂停，待用户明确继续。
- “检查模拟状态”折叠区显示会话、提示版本、drop 绑定与回执；另有后台完成和保存确认的便捷演示按钮。

## 仿真边界

所有文本回复、解析与保存均为本地 fixture；选择或拖入用户文件只保留当前页面内的名称、类型等资料，不读取其真实正文，也不把它写到任何位置。外部文件收到的内容反馈不能作为真实解析质量证据。工作区是场景中的文件边界示例，UI 原型不取得文件权限。

会话、草稿和回执只在页面内存；没有业务 API 请求、LLM 调用、数据库或 localStorage；浏览器仍会加载本地静态资源。重置清理定时器与模拟状态。唯一浏览器导航更新是方向参数；原型控件仅存在于此专用入口，不导入生产 App。

真实浏览器操作可核验按钮、拖放、草稿、布局和一次性回执。跨 App 拖放、原生窗口焦点、全屏空间、多屏、VoiceOver 与真实 Provider 运行需另行验收。UI 与状态模型的模拟不能替代这些系统证据。
