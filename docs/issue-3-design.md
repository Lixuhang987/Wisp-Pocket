# Issue #3 设计讨论

本文记录 [前后端状态所有权收敛与中间层削减 #3](https://github.com/Lixuhang987/Wisp-Pocket/issues/3) 评估中已确认的修订约束。两轮共六项约束已确认，范围与验收原则的评估已收敛；GitHub 正文尚未同步，本文不代表原 Issue 已可直接实施。

## 已确认范围

- 本轮保持现有用户行为；自动重连、订阅恢复和待答请求补发另立需求，不作为既有能力或本轮验收项。
- 保留 [既有后端边界](./adr/0001-backend-state-ownership.md)：core 管理 Thread 业务与生命周期，agent-server 管理连接与协议适配。取消必须删除 Router 和 Persistence 的预设；移除代码前逐项确认职责及其归属。
- 全仓库 `types/`、`utils/` 标准化独立于本轮；本轮只整理涉及模块，避免无关路径迁移掩盖状态边界变化。
- 后端只精简有证据证明冗余的转发或重复处理；若没有值得实施的精简项，允许本轮后端不改代码。

## 前端状态边界

| 状态类别 | 职责归属 |
| --- | --- |
| 后端已确认的事实 | 后端拥有正式历史、执行状态和待答请求；前端维护展示投影。 |
| 尚未提交或尚未确认的输入 | 前端管理草稿、等待派发的输入及交接期间的临时展示；沿用现有发送顺序和确认规则。 |
| 界面偏好与临时交互状态 | 由前端拥有，保留各自现有的持久化范围。 |

- store 的拆分依据上述职责，不预先规定必须拆成四个文件。输入交接和状态投影需要独立说明，不能把所有前端状态都视为后端事实的缓存。
- 等待 Turn 的输入队列与等待连接就绪的传输缓冲服务不同阶段，不能仅因两者都缓存输入就合并；本轮不增加重试或新的确认机制。

## 验收原则

- 取消删除超过 200 行、固定四个文件且每个小于 200 行、测试数量不下降等完成指标。
- 审核状态修改入口及后端连接与业务职责的归属；验证输入不重复派发、流式展示、请求结束，以及保存失败、删除和关闭时的现有行为与时序。
- 保留真实数据库链路测试；可控依赖用于验证故障和时序，不能用 mock 测试数量替代持久化行为保障。
