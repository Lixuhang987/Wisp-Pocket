# 桌宠：轻量接续工作

- **模式**：Operate；角色是交互入口，其动画不将 surface 转为作品浏览模式。
- **范围**：桌面角色、首次文字、资料拖入、当前气泡、建议与回复、悬停统一浏览、大小控制；主入口 `apps/electron-shell/src/activity-window/App.tsx`。
- **用户与频率**：希望在当前桌面轻量交付资料和回复的用户；角色常驻，交互按需。
- **成功条件**：点击后可直接输入，拖入目标明确，能理解接收与处理状态，继续当前任务，同时保留桌面其他区域的正常交互。

## 当前 surface 合约

**现有交互基线**：点击桌宠唤出并聚焦回复框，常态展示最新非空 assistant 消息及当前建议；仅 hover 对话区时展示当前 Thread 的全部用户 / assistant 历史消息，移出立即回到最新消息，输入焦点与草稿保持。再次点击隐藏整套对话，后台更新不解除主动隐藏。这里的“展开”专指悬停浏览，没有点击锁定或固定宽面板状态；后续多宠 / 身份 / 历史选择规格须保留这条交互，除非用户明确提出改变。

- **THESIS**：从角色点击或资料拖入开始，以固定回复框接续工作；完整任务过程仍可从 ThreadWindow 访问。
- **OWN-WORLD**：保留月见八千代图集；气泡与控件继承共享主题，窗口空白区域透明并按命中区域穿透。
- **STORY**：点击角色唤出并聚焦 → 输入，首次发送才创建 Thread → 继续回复；也可拖到角色新建并读取，或拖到对话区追加。悬停查看完整内容，移出仍可输入，再次点击隐藏并保留草稿。
- **FIRST VIEWPORT**：启动仅显示角色；唤出后右侧对话列约 210px，底部约 44px 回复框为固定锚点，其上依次为全部当前建议和最新非空 assistant 气泡。无建议不占位，正文常态显示开头最多三行；无历史时可仅显示空回复框。右键角色打开大小控件。
- **FORM**：现有透明桌面浮窗，采用仅角色 / 紧凑对话 / 悬停展开三个布局状态；本次合入已实现的 Issue #5 方案，未进行新概念选择，seed key 不适用。
- **FINISH**：以合入的 Issue #5 实现为当前记录；保留原功能分支的专项与实机证据范围，本次合并未重新进行实机视觉验收。

## 状态与约束

| 状态 | 当前行为 |
| --- | --- |
| 启动仅角色 | 恢复历史不自动展示对话；后续新建 Thread 可显示对话，但不主动聚焦 |
| 主动隐藏 | 点击角色切换整套对话显隐，唤出时聚焦回复框；后台更新、错误和新 Thread 不解除主动隐藏 |
| 无历史/首条文字 | 打开空回复框不创建 Thread；首次发送等待匹配的持久接收确认，失败保留可编辑草稿，确认不擦掉期间新编辑的文字 |
| 拖入 | 角色提示新对话；对话区提示追加；松手时确定目标，再读取文件 |
| 接收/执行/待处理 | 显示相应状态；执行期间回复仍可提交并由后端排队 |
| 等待回复或授权 | 建议与自由输入继续任务；权限与工作区请求在展开对话中呈现 |
| 悬停 | 仅进入对话区展开；历史、完整最新正文、当前建议和交互请求共用一个滚动容器，回复框在其外；每次进入回到底部，同次上翻期间不抢回底部 |
| 移出/保持输入 | 立即回常态，保留回复框位置、焦点和草稿；自动聚焦本身不触发展开 |
| 内容溢出 | 常态和悬停均在上方容器边界裁剪；常态正文与建议不单独滚动，悬停通过统一容器查看完整内容 |
| 失败/连接变化 | 接收错误、任务错误与连接状态可呈现；桌宠有自己的重连恢复逻辑 |
| 调整角色 | 拖动位置、右键调整大小；对话字号和列宽不随角色同比缩放 |

当前选择按 Thread 创建时间确定，没有桌宠内手动切换入口；工具调用不进入桌宠历史。角色拖动结束不误触显隐切换；附件读取期间发生主动隐藏时，后续提交或错误不弹回对话。
