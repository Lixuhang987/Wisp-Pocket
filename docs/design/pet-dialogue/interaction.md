# 桌面布局与交互层次

推荐 A“口袋对话”为默认，以 C 的稳定阅读能力补足长任务；B 留作高频资料交付的可选试验。推荐基于任务覆盖与原型观察，尚不是用户试验选出的胜者。三个方向共用 [任务书](./brief.md) 的素材、内容与场景。

## 始终认得出在和谁说话

每只完整角色旁保留短名称；悬停、键盘选中或任务需注意时显示工作状态。对话面板标题始终含“桌宠名 · 对话标题”，下方可见默认文件工作区。角色只表达状态类别，文字给出准确事实；更换皮肤不会悄悄切换历史。

| 层次 | 默认可见内容 | 进入 / 退出与目的 |
| --- | --- | --- |
| 常驻角色 | 完整桌宠、名字、必要的未读/需决定标记 | 启动只显示角色；后台消息不抢焦点 |
| 紧凑对话 | 最近面向用户的回复开头、所有当前建议、回复框 | 点击角色显示/隐藏；无 Thread 也能直接起聊 |
| 悬停浏览 | 同一滚动流中的历史、完整最新消息与建议 | 只由对话区悬停展开；每次从底部开始，沿用已有紧凑方案 |
| 固定会话面板 | 连续历史、附件、工具详情、请求、编辑区域 | 点“展开”或键盘命令进入；离开鼠标不会收起，关闭回到原角色 |
| 就地管理 | 历史抽屉、伙伴切换、角色编辑、工作区/模型设置 | 从当前角色入口打开，关闭恢复原 Thread 和草稿 |

常态以回复框为锚点，建议和最近消息向上堆叠，空区域不占位。沿用已讨论的约 210px 列宽、约 44px 单行回复框与三行正文上限；这是轻量扫读尺寸。长输入自动增高到上限，继续编辑可主动展开 360–480px 的会话面板。展开不能另建 Thread，也不能重新注入首轮输入。

悬停只是快速预览通道，完整能力也可通过点击与键盘进入。权限问题、搜索和多步设置使用固定面板，避免鼠标移出后消失。手动固定多个面板时允许并排阅读，只有用户明确点击的输入框获得键盘焦点。

## 两种显示方式，同一套数据

### 三宠全部同屏

可把三只完整桌宠分别放在桌面上，每只独立拖动、缩放、打开历史；并非三个小头像代替角色。默认角色相邻但不重叠，可分别靠边。默认只展开最近主动操作的对话面板，其余保留角色与小标记；用户可固定多个面板。空间不足时由用户选择收起部分或切单位置，不静默隐藏运行中的任务。

### 单个位置切换

席位保留一个完整角色，旁边“伙伴”按钮显示另外两位名字、状态和待决定数。选择后换成对应完整角色，并恢复该宠上次主动选择的对话、草稿、工作区筛选与隐藏状态。背景任务继续。折叠的两位仍可从同一入口找到，不因动画不可见而被暂停。

单位置收到其他宠物的重要状态时，席位出现“另有 1 项待决定”；点击展开清单并定位到真正的宠物与 Thread。绝不把后台请求插进当前宠物的回复中。

## 手势与键盘

| 动作 | 固定语义 | 反馈与冲突处理 |
| --- | --- | --- |
| 点击角色 | 显示/隐藏紧凑对话；显示时聚焦回复框 | 无历史也有回复框；不自动提交 |
| 拖角色 | 移动席位 | 越过移动阈值后不再触发 click；Esc 取消移动 |
| 拖资料到角色 | 给这只宠物创建新对话并 inspect | 高亮明确显示宠物名与“新对话”；没有 hover 发起任务 |
| 拖资料到对话面 | 追加该 Thread 并 inspect | 提示标题和接收宠；最终 drop 固定路由 |
| 点击历史图标 | 打开本宠历史抽屉 | 默认“这位伙伴”，可切所有伙伴；绝不只依赖右键 |
| 右键角色 / 更多 | 大小、固定、显示方式、角色设置 | 高频回复、Stop、历史也有可见按钮和键盘入口 |
| Enter / Shift+Enter | 发送 / 换行 | IME 组合期间 Enter 只确认候选，不发送 |
| Escape | 先退当前子面板，再收起展开面，再隐藏 | 不删除草稿、不答权限、不取消运行 |
| 现有全局热键 | 唤起当前席位的这位伙伴 | 确认接收宠；无选择时用用户设定的默认伙伴 |
| 切伙伴快捷操作 | 通过可配置快捷键或名称选择 | 不占用输入框方向键；系统冲突由设置提示 |
| 停止按钮 | 停止标题中明确的当前 Thread | 始终与发送并存；“停止全部桌面操作”另有清楚标签 |

角色拖动与文件 drop 是不同输入路径，不把整个角色区域设成会吞掉 pointer events 的原生 app-region drag。每个有效命中区域随实际表面裁剪，空白透明区域保持穿透；窗口、角色缩放与对话字体分开。

## 前台上下文与遮挡

打开聊天只在用户点击/键盘发起时激活；接收材料、进度和完成默认不抢前台应用。结束或 Esc 返回前台焦点需要保存并校验原窗口仍存在；不复用已有 PromptPanel→ThreadWindow 的聚焦顺序而造成焦点拉扯。

靠右时对话向左展开、靠左时向右，顶端不足时缩短可滚动区域；完整角色与回复框优先可见。用显示器工作区和 DIP 坐标约束窗口，不用像素直接乘 Retina 比例。屏幕拔出后把不可见席位迁回可用工作区，保留身份及可恢复的原屏位置。

Spaces、全屏应用与 Stage Manager 提供用户设置“只在当前工作空间 / 跨空间跟随”。默认不盖在独占演示或全屏内容上；通过全局热键仍可唤起。真实行为必须按 [平台研究](../../research/2026-09-14-pet-platform-hci.md) 的原生门槛验证。

## 陪伴感来自回应方式

接住资料时转向材料，处理中使用轻微专注动作，待用户决定时保持可辨的等待姿态，完成后短暂回应并回到 idle。名称、称呼、回复节奏和结果表达可以因档案不同，但成功、失败、许可和队列的语义保持一致。

不靠随机闲聊、饥饿惩罚或持续震动争取注意。声音默认静音，语音为可选按住说话/明确开启的模式；流式文本始终可读。减少动态效果使用静态帧，状态仍有文字；不靠颜色或角色姿势独自表达“需要许可”。

## 可访问性

交互区域最小目标按平台能力确定并用 24pt 以上作为起点，图标有可读名称；微小角色可通过可见标签与键盘选择。固定面板具有明确标题与焦点顺序，读屏只播报阶段变化和等待用户的内容，不逐 token 朗读。字体放大时转固定面板并保持单一滚动层，完整功能不依赖 hover、拖拽、色觉或音频。
