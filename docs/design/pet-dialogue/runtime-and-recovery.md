# 任务、决定、并行与恢复

## 把显示状态和执行事实分开

当前 core 的运行状态只有 idle/running/failed/interrupted。下列更细的文字是从输入、Turn、请求与连接派生的 UI 表达；正式新增运行状态时必须由 core 拥有，不在 renderer 另建任务机。

| 用户看到的状态 | 事实来源 | 此时能做什么 |
| --- | --- | --- |
| 正在接收 | 文件读取/上传仍在途，未确认持久化 | 查看接收对象，取消尚未提交的交付 |
| 已接收 · 待处理 | 已持久化输入还没有对应 turn.started | 查看队列、继续输入；不重复提交 |
| 正在读取 / 处理中 | Turn 与真实读取/工具进展 | 追加输入、查看详情、停止 |
| 等你回复 | assistant 以普通消息提出问题或建议 | 普通回复即可继续，等待不会因超时自行执行 |
| 需要许可 / 选择工作区 | 有效 ServerRequest | 检查目标与后果，以 ClientResponse 回答 |
| 等候桌面控制权 | 另一 Thread 持有宿主操作资源 | 查看占用者、取消等待、继续其他独立任务 |
| 已完成 | 结果持久化成功，Turn 完成 | 查看/复制/带走产物，不用动画代替证明 |
| 连接中断 | UI 与服务连接不可用 | 保留草稿，查看最后已确认状态；不声称任务一定停了 |
| 已中断 / 失败 | 后端终态及失败原因 | 查看已发生的效果，明确决定是否继续 |

同一宠可以有多个活跃 Thread。宠物本体只展示汇总：优先“需决定”，其次失败、运行、未读；点开状态列出各 Thread。用户正在编辑的那段对话不会因汇总优先级变化而切换。动画可选当前可见 Thread 的状态，名字旁汇总仍覆盖后台状态。

## 待决定清单

每宠历史上方提供“待我决定”，单位置的伙伴选择器显示其他宠数量；全局入口只是同一请求事实的聚合视图。每项显示宠物、Thread、请求对象、提出时间与是否仍有效，点击定位原对话。它不是新的待办任务系统。

Permission 与 Workspace 请求保留独立回执路径，普通建议按钮保留 UserInput 路径。请求回答后禁用本地按钮，最终以 request.resolved/snapshot 为准；另一个界面抢先回答时显示已处理，不重复执行。后台请求只能唤起标记或用户许可的通知，不自动换宠或抢键盘。

### 超时与稍后处理

当前 Permission/Workspace 有 60 秒时限，不能在设计里假装永久待答。首个实现切片保持此协议，UI 显示剩余有效期；超时后保留历史原因及“重新检查后继续”的入口，旧按钮失效。用户重新发起后由模型重新观察目标并生成新请求，不重播已过期工具调用。

后续若提供“稍后处理”，它应释放当前执行和宿主租约，把待确认意图作为 Thread 内可恢复状态保存；回来时重新检查文件/页面与权限，再生成新请求。不能简单无限挂住一个 Promise，也不能让服务重启复活旧 requestId。该能力单独验收，不与普通建议的无限等待混称。

## 权限文案不被角色遮住

权限卡标题可写“小八想保存这份邀请”，但操作、工具、文件/对象、影响范围和范围选择是中性的稳定字段。默认提供允许一次与拒绝；高级选项明确写“以后对所有桌宠记住此工具的决定”，链接永久规则与撤销入口。当前 always 按完整工具名称全局匹配，不按参数，也不按桌宠。

不同角色的可用工具集要由后端过滤/调用检查生效；全局已允许也不能把一个被该角色禁用的工具重新暴露。系统录屏、辅助功能和麦克风授权属于 App/进程，不伪装成每宠 OS 权限。角色不会用失望、卖萌或关系压力诱导用户允许。

## 并行执行的边界

独立模型思考、网络读取和不同文件的工作可并行；默认总并发上限可配置，队列清楚显示，不用桌宠数量直接决定启动几个独立服务进程。同一 Thread 仍串行处理 UserInput，其他 Thread 不受其等待阻塞。

所有对前台 App 的鼠标、键盘和依赖该前台状态的截图→操作链需要共享宿主仲裁。每次操作序列持有带 Thread/Turn 身份的租约；其他宠显示“等候小八完成桌面操作”。获取租约后重新观察界面，不能继续使用等待前的坐标或截图。等待模型长推理、用户许可时尽可能释放租约，下次重新获取并检查。

租约与任务取消有明确过期、断连和回收规则；Provider 不接受过期持有者的后续输入事件。用户主动操作前台时可暂停自动化并说明原因。全局“停止桌面操作”停止宿主事件注入，不等价于删除各 Thread。当前 Dynamic Tool 协议没有完整远程 cancel，需扩展取消请求/确认，并由 Host Automation 的真实执行层响应后才能声称停止。

同一路径的写入要检查从读取到写入期间的版本变化，或在实际写入区间由共享文件 adapter 协调；冲突时展示比较与目标，不默认最后写入覆盖。任意外部 App/MCP 不在本地租约控制之内，界面需说明无法确认的外部效果并请求重新核验。不要持文件锁等待用户或 LLM。

## 停止、排队与重试

Stop 应固定指向用户当前看到的 Thread。运行中追加仍按既有持久队列接受，UI 说明“这条会在当前任务之后处理”；若用户要改变正在做的事情，提供独立“停止后修改”动作。

多宠版本建议 Stop 同时暂停该 Thread 的未开始队列，避免刚停止一项就自动启动下一项；这是相对既有实现需要明确新增并持久化的行为，不能只接一个按钮就算完成。提供“继续待处理”和“取消待处理”，取消需对每条已接收输入留下可见结果。停止一个 Thread 不停止其他宠。

重试从最后已确认状态继续；可能产生外部效果的调用不自动重放。可幂等读取可由用户一键重试，写文件、发消息、点击购买等则先核对是否已发生。错误发生在读取、模型、工具或持久化不同阶段，要有各自可执行的下一步。

## 恢复矩阵

| 事件 | 必须恢复/保留 | 不应该自行发生 |
| --- | --- | --- |
| 切宠、切席位模式、隐藏 | 每宠当前 Thread、草稿、后台状态 | 取消任务、合并历史、重新提交 |
| renderer 崩溃 | 从服务恢复 snapshot，从本地恢复未发送草稿 | 服务下线或把草稿算已接收 |
| 短时 socket 断连 | 带相同身份重新 list/subscribe/resume，核对 opId 接收 | 用新 opId 盲目重发 |
| 服务重启 | 已保存 Thread、附件、待处理输入；残缺 Turn 为中断 | 自动重跑在途动作或旧许可 |
| 目标 Thread 离线时被删除 | 权威列表清理选择；未投递资料给出原目标失效 | 追加到另一段最新 Thread |
| 桌宠归档 | 历史仍可从“已收起伙伴”找回，已有任务可达 | 级联删除资料或把任务变成别的角色 |
| Workspace 注销 | 历史与 Blob 仍在；默认位置提示失效 | 删除真实目录或自动选另一个根写入 |
| 屏幕移除/电脑睡眠 | 可见席位重新夹取，连接重新核验 | 因恢复动画清除任务或伪报完成 |

## 通知、安静与隐私

普通进度在当前会话可见，后台只更新标记；需要决定和失败优先但不强制抢焦点，多个事件合并。用户可选每宠/全局静音和安静模式。仅在用户明确启用时用系统通知，并准确标记紧急程度，不把普通完成提升为 Time Sensitive。

展示模式可选仅名字与状态，敏感结果点击后读取。锁屏和屏幕共享下的隐藏需要系统实测，不能用窗口标志宣称绝对不被捕获。语音作为独立后续通道时，在开始录音固定目标宠/Thread，切宠不改变这句话的接收者，录音/上传状态始终清楚，支持文字等价入口。
