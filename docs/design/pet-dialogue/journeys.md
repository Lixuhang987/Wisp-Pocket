# 从桌宠开始并完成的任务场景

状态：推荐的端到端设计，2026-09-14；以下是待实现/验收的行为，不是已完成测试。能力编号对应 [覆盖矩阵](./capability-matrix.md)，交互与归属规则分别见 [交互层次](./interaction.md)、[历史与输入](./history-and-input.md)、[身份与角色](./model-and-persona.md)。名词沿用 [Desktop Experience](../../../apps/desktop/CONTEXT.md)、[Conversation Runtime](../../../packages/core/CONTEXT.md) 与 [Host Automation](../../../apps/host-automation/CONTEXT.md)。

所有样例使用可丢弃的“读书交换日”活动草案、图片和文件夹。A 口袋对话、B 桌面长桌、C 对话手册运行同样的任务、角色和异常；三宠完整同屏/单槽切换是每个方向共同具备的显示方式。不得用假成功消息替代持久接收、真实权限结果或文件产物。

## 发起、交付与连续对话

### UC01：没有历史，也能直接问一句

关联 C01、C02、C03、C37、C40、C51。

- **触发**：首次打开产品，尚无 Thread，用户点击八千代，输入“帮我把读书交换日的准备事项分成三步”。
- **输入与事实变化**：桌宠在空态直接给出回复框；发送时创建归属八千代、使用其当前角色快照的 Thread。没有显式 Workspace 也允许随聊。创建成功与输入持久接收分别确认，之后才把文字从草稿变为已接收消息。
- **可观察结局**：回复从八千代旁出现，用户可自由追问或选建议；历史入口出现这段对话。整个链路无需先拖文件、打开 ThreadWindow 或建立项目文件夹。
- **失败与验证边界**：模型未配置时，从原宠物进入所需配置并保留草稿；创建/保存失败仍可恢复原输入。不确定接收结果时先对账，不再次创建不相关 Thread。原型可验证路径存在，真实创建、持久化和模型请求需集成证据；配置若仍跳独立 Settings，只计“无 ThreadWindow”，不计全程宠内完成。

### UC02：三位伙伴完整在场，单槽也不丢工作

关联 C05、C38、C39、C42、C43、C60。

- **触发**：用户在八千代的“伙伴”中添加写作搭档 Miku，再复制档案建立行动助手小八；小八暂用与八千代相同的外观。
- **输入与事实变化**：每次保存产生独立身份，复制不复制历史。用户选择三宠完整同屏，分别移动到桌面边缘，给三者各留一份不同草稿；随后切成一个位置轮换。角色预览使用独立临时对话，与正式历史分开。
- **可观察结局**：同屏时三只完整形象和名称都可见、可投递；单槽能按姓名和状态找到另外两位，并恢复各自历史选择和草稿。固定多个会话面可同时阅读，只有主动点击的输入框拥有焦点。缩放只影响角色与命中，不改变正文尺寸或执行任务。
- **失败与验证边界**：相同皮肤不能导致身份混淆；空间不足不静默删掉第三只。归档/停用一位伙伴保留旧历史、处理运行与触发依赖，恢复不补跑过去事件。布局变化不能产生新 Thread、复制消息或暂停隐藏宠物。窗口命中与位置持久化需原生测试，预览 mock 不证明模型遵循人设。

### UC03：PDF 交给八千代，Miku 写作，小八保存

关联 C02、C12、C23、C24、C26、C28、C32、C35、C36、C37。

- **触发**：用户在 Finder 看到活动 PDF，希望最终得到已保存、可直接使用的邀请文案。样例 PDF 明确记有“周六 15:00、社区活动室”，但没有报名方式。
- **输入与事实变化**：把 PDF 松手到八千代本体，形成其新 Thread；先保存材料副本，再以 inspect 读取。八千代区分实际读到的字段与缺失项。用户选择“交给 Miku”，检查将带走的摘要和 PDF，确认后在 Miku 下创建新 Thread，源 Thread 保留原主人；默认转交只授权阅读。用户对 Miku 明确说“按这些信息写邀请，报名方式先留空，不发送”，在会话面内补好报名方式并确认正文。随后把确认后的正文交给小八，再明确选择“保存到读书会，文件名活动邀请.md”；小八在正常执行阶段检查 Workspace 与 Permission，仅在实际需要时请求决定。
- **可观察结局**：文件真正写入后，小八给出文件名、工作位置和可用的打开/Finder入口；用户核对文件内容与确认正文一致。八千代的资料记录、Miku 的改稿过程和小八的保存记录各在自己的历史中，并可沿转交来源回溯。该闭环是一个用户任务，不能用前两步成功掩盖最后保存失败。
- **失败与验证边界**：PDF 无文本时不得虚构活动信息；摘要转交前必须可检查，不能附带源 Thread 全部隐私历史。隐藏小八不丢待决定请求；源 Thread 删除后的材料引用、保存冲突和已移动产物需独立变体。浏览器原型只证明路径和状态解释；实际 PDF、跨 Thread 引用、文件写入与可打开成果必须使用可丢弃真实样本验收。

### UC04：四类资料、两种落点与延迟交付

关联 C06、C07、C08、C09、C10、C11、C12、C13、C14、C15、C23。

- **触发**：用户分别从外部 App 给伙伴一段文字、一个 URL、一张图片和一份 PDF；每种都要试“开始新对话”和“补到已有对话”。
- **输入与事实变化**：逐类执行角色本体/会话面两种松手位置，共八条独立路径。hover 只标候选，最终成功 drop 才固定宠物、Thread或新建意图、默认 Workspace 和交付标识；经过别的角色不创建空历史。对话面追加不新建 Thread，角色本体新建不污染旧对话。多项材料逐项呈现接收状态，延迟文件物化仍使用原投递记录。
- **可观察结局**：每次实际接收都与高亮提示的姓名和会话一致；同一项只有一份持久用户输入。用户在等待期间切到第三只宠物，材料仍进入松手时指定的对象。没有拖拽能力时，文件选择与粘贴预览可以完成相同任务；粘贴草稿可先移除，drop 松手则已经表达 inspect 交付，不追加一次无意义的发送步骤。
- **失败与验证边界**：分别记录 URL 登录墙、视觉模型缺失、损坏/加密/扫描 PDF、空白文本、多项部分失败、目标被归档/删除。失效目标不改投默认宠物。Finder 成功不等于 Mail 的 File Promise 或浏览器图片成功；每个来源 App 与类型要有真实原生记录，未支持类型如视频/文件夹应明确说明替代方式。

### UC05：中文长草稿切来切去仍属于原对话

关联 C04、C05、C26、C42、C54。

- **触发**：用户对 Miku 编辑一段带换行的邀请文案，输入法候选尚未确认，另一只宠物完成了资料整理。
- **输入与事实变化**：后台事件只改变所属宠状态。用户主动切伙伴、打开旧 Thread、再切显示方式；每份草稿与附件分别保存。IME 组合中的 Enter 只确认候选，Shift+Enter 换行；最后明确发送时才提交。长编辑从紧凑区展开到固定面板，仍是原输入和 Thread。
- **可观察结局**：返回 Miku 后文字、换行、附件与编辑状态可恢复；另一宠的完成不把文字接走。用户在固定阅读区的滚动位置保持，hover 快速预览则遵守其回到底部的独立约定。收起不会清空草稿或停止运行。
- **失败与验证边界**：测试组合输入中切宠/切历史/窗口失焦/按 Esc，不能因 DOM 卸载丢字或发出半成品。前台外部编辑器持续输入时触发三宠事件，字符不进入隐藏输入框。原型能查草稿键与选择关系；中文/日文 IME、key window 和焦点恢复必须原生验证。

## 找回、配置和控制任务

### UC06：找回两周前的工作，再整理和导出

关联 C17、C18、C19、C20、C21、C22、C23、C25、C60。

- **触发**：用户只记得两周前讨论过“交换书目”，不知道是哪只宠物、哪个 Workspace，希望继续工作并导出需要的记录。
- **输入与事实变化**：从当前宠物历史开始，默认查本宠；未找到时主动切全部伙伴并按 Workspace 筛选。搜索样本包含只出现在消息中部、未出现在预览里的关键词。命中后显示主人，打开时切到该宠与原 Thread，恢复创建时角色快照及材料。用户改名、置顶、导出选定消息；处理完成后归档，并从归档区恢复。删除另一段可丢弃旧对话作为单独变体。
- **可观察结局**：重新打开和重启后元数据仍成立；导出只含用户选择范围，实际文件可读。其他宠草稿保留，原会话没有被当前人设接管。归档的运行/待决定任务仍有入口，归档/恢复不重新运行内容。
- **失败与验证边界**：没有 OCR 的附件正文不能假装能搜；跨宠结果不是复制成当前宠说过的话。删除需处理运行终止和共享附件引用，不能删除已经转交给其他 Thread 的唯一可用副本。上千历史的分页和性能属于 P3，不能由十条内存数据演示证明。

### UC07：长回答、工具过程和真实文件都能在宠物旁看清

关联 C26、C27、C28、C29。

- **触发**：Miku 给出长邀请方案、对照表和代码片段；用户希望完整阅读、复制正文，并核查另一只宠物声称保存的文件。
- **输入与事实变化**：在紧凑区扫读后显式展开会话面板；正文保留格式，执行记录按需展开，呈现真实读取、工具输出与失败位置。用户复制指定正文或代码，点击成果卡打开/在 Finder 显示。面板开关不创建新 Thread 或重新提交输入。
- **可观察结局**：复制内容完整且与可见结果一致；只有实际文件存在且保存完成时提供成功成果。离开鼠标不会关闭固定面板，用户可以边看外部资料边继续；全过程不需要 ThreadWindow 来看工具细节、Stop 或结果。
- **失败与验证边界**：工具失败但模型文字说“完成”时，以执行事实为准；文件被移走/删掉后成果卡报告不可用。生成文档/图片 mock、复制按钮点击成功、可滚动截图均不证明文件真实可用；需核验实际产物与失败变体。

### UC08：改工作方式和模型，旧对话仍可解释

关联 C16、C25、C38、C39、C40、C41。

- **触发**：用户希望 Miku 今后回复更简短，使用另一已配置模型，并常用一个邀请写作 Append Prompt；同时想启用一个外部工具来源。
- **输入与事实变化**：从 Miku 设置保存角色提示新版本，先在标明用途和费用的独立预览里试用。新对话读取新快照；旧对话仍显示原设定，如要应用新版则检查摘要并新开。模板从回复框选择，只追加到此次 UserInput。模型服务与凭证从统一配置入口管理，档案明确显示继承或覆盖；MCP 配置展示保存、待生效和实际连接状态。
- **可观察结局**：模型请求实际使用声明的模型，角色快照与模板归属可查；旧 Thread 不因当前设置变化改写历史。工具列表来源清楚，受限伙伴即使共享系统权限也不能调用被后端禁用的工具；角色外观与名字变化不改变这些规则。
- **失败与验证边界**：无效 Key/不可达服务/非视觉模型可在原宠物修复且保留材料；如果 MCP 仍需重启，则明确提醒并经恢复路径继续，不宣称已热加载。保存 UI 成功不等于 Runtime 已采纳，需检查实际请求、工具声明和重启回读；预览不代表真实外部操作已获授权。

### UC09：选工作位置，授权一次或记住，然后撤销

关联 C32、C33、C34、C35、C36、C37、C39。

- **触发**：小八收到明确保存邀请的请求；当前尚未选文件位置。用户希望这次指定“读书会”，并了解某工具的永久授权如何影响其他伙伴。
- **输入与事实变化**：小八在自己的固定会话面展示有效 Workspace 候选；必要时从就地管理注册目录，取消则不执行写入。需要 Permission 时显示工具、实际目标、参数/后果和四种 once/always 决定。用户先选本次允许，再在另一可丢弃操作中选择永久决定；界面明确说明它按 Tool 名称对所有参数与 Thread 生效。随后用户进入权限管理撤销此规则。
- **可观察结局**：只接受当前请求允许的工作区；永久决定会在另一宠物的同 Tool 调用上按真实策略生效，不误称“仅给小八”。撤销后后续调用重新按策略处理，重启后也一致。inspect 阶段和每宠后端能力限制始终不能被永久允许绕过。
- **失败与验证边界**：覆盖永久拒绝、无效候选、双端同时答复、请求过期、回答前切成单槽隐藏该宠。只能有一次有效回执，过期后不伪造执行成功。拒绝不触发情绪施压，已有授权不重复强迫确认；工作区默认元数据不能作为 Thread 级访问隔离的证明。

### UC10：运行中补充要求，能看队列也能真正停止

关联 C02、C29、C30、C31、C35、C53。

- **触发**：八千代正在处理一份慢资料，用户又发送“先给简版”和“补一个表格”，后来希望改掉后一个要求并停止当前处理。
- **输入与事实变化**：两次输入可立即提交到后端，持久接收后分别显示待处理，不在 renderer 私建执行队列。用户在待处理清单修改/撤回尚未开始项；服务端确认状态后才更新。Stop 针对标题中的当前对话，中断实际 Turn，尚未开始输入保留为待用户继续/撤回的可见状态，停止后不悄悄自动启动下一项；此队列处置是目标设计，实施时需核对并补齐现有中断语义。
- **可观察结局**：已接收、待处理、处理中、正在停止和已停止可区分；用户能明确继续剩余要求。关闭面板不等于 Stop，停止八千代不取消 Miku 的独立写作。已经产生的文件变化如实保留在执行记录，不能用停止动画宣称回滚。
- **失败与验证边界**：撤回时该项已开始则转为说明/Stop，不接受仅删气泡的假撤回。分别在模型流式、Tool 调用、Permission 等待与宿主排队阶段停止；对照后端终态和产物。逐项修改/撤回需要持久协议支持，原型不能证明该能力已存在。

## 外部入口与内置功能

### UC11：选区、截图和快捷键都回到预期伙伴

关联 C15、C44、C45、C46、C54。

- **触发**：用户在浏览器选择一段活动规则，或截取海报局部，按现有全局快捷键希望交给 Miku 解释。
- **输入与事实变化**：打开输入意图时固定接收宠物。纯文字快捷入口可直接唤起该宠；保留 PromptPanel 时明确显示目标，主动选区/截图先成为可见附件预览，确认后提交；不能默认附带整屏、剪贴板或后台窗口内容。输入面在等待时即便单槽换成小八，原材料仍送给最初标明的 Miku。
- **可观察结局**：提交后在 Miku 对应会话看到持久输入、来源和后续结果；不自动打开 ThreadWindow。取消采集返回来源 App，既有草稿不丢，用户自己继续输入时焦点没有被后台结果拉走。
- **失败与验证边界**：选区读取失败、截图权限拒绝、源窗口关闭、输入确认丢失分别可恢复；失败不能偷偷扩大采集范围。原生系统权限、附件范围和焦点顺序需实际测试。经过 PromptPanel 的路径在统计中明确属于“无 ThreadWindow”，不能借回流结果把整段算全程宠内。

### UC12：自动触发有固定接收者，失败不是无事发生

关联 C35、C47、C48、C59、C60。

- **触发**：用户为“周五提醒准备读书会”设置 System Clock 规则交给八千代，或为指定收藏夹新增链接设置整理规则交给 Miku。
- **输入与事实变化**：在宠物入口管理 AgentTrigger Instance，明确包配置、目标档案及新建/续接策略。Event 触发后保留结构化来源与关联，按配置提交给目标宠。用户此时正在小八会话中输入，不因后台创建 Thread 改变选择。
- **可观察结局**：所属宠有待看结果/待决定标记，历史能区分手动输入和自动来源。用户从单槽汇总定位目标任务，可完成必要决定和查看结果；编辑或停用规则影响未来事件，不重放旧事件。
- **失败与验证边界**：浏览器连接失效、目标已归档、配置错误、服务不可用、持久提交失败都留下可操作记录，不能吞错或改投默认宠物。重试必须核对已接收状态。此路径包含真正的原生触发、桥接与后台执行，浏览器定时器模拟不算接通。

### UC13：需要“刚才看的资料”时才开启与使用 Context History

关联 C35、C49、C59。

- **触发**：用户问八千代“刚才看的那页活动规则是什么”，但 Context History 当前未启用。
- **输入与事实变化**：宠物说明没有已有观察资料可用，提供明确的内置功能入口；用户主动启用时看到记录范围和状态，必要的系统权限按实际需要请求。启用后的 Activity Sample 由所属模块采集，回答按需调用 Tool 并展示来源，不把启用本身当作向每个 Thread 注入全部历史。
- **可观察结局**：用户可验证采样开始、最近状态及引用的时间/窗口证据；之后从同一入口禁用，采集与相关工具入口随之停止，关闭面板本身不改变开关。既有数据保留的含义清楚，不能把禁用说成已删除所有记录。
- **失败与验证边界**：拒绝屏幕录制/辅助功能、无首次采样、截图不可用时如实降低能力。当前模式没有“停止采集但继续查询”的独立开关，不能只画一个按钮就宣称具备。需要实际模块状态、存储和系统权限证据；不得用活动摘要 mock 证明已观察到真实桌面。

### UC14：在伙伴旁录制一次流程，下次再用

关联 C27、C29、C35、C50、C58。

- **触发**：用户希望小八记住一个可丢弃测试 App 中的重复操作流程，下次按相同方式执行。
- **输入与事实变化**：从宠内能力设置明确启用 Automation，开始 Recording Session；界面持续显示录制状态并提供停止。停止后检查 Automation Trace、保存有名称和版本的 Policy，稍后或重启后明确选择该版本运行；进度、决定与停止仍在该宠入口。
- **可观察结局**：实际录制、保存和 Automation Run 与界面记录对应；成功由结果断言/产物支持。一次失败产生可检查的 Repair Request，用户明确提交修复材料后即使合入 Repair Patch，也仍展示“待重跑验证”，不会直接显示流程已修好。
- **失败与验证边界**：覆盖录制权限拒绝、运行中关闭面板、禁用功能、退出应用、匹配失败和用户停止。禁用或退出停止任务但不抹掉 Policy/历史；正常退出等待取消结果落盘。完整链路依赖真实宿主能力，不能用按播放键后递增进度条代替。

## 并行、恢复与系统边界

### UC15：三位伙伴同时帮忙，共享桌面却只有一个控制者

关联 C27、C29、C32、C35、C58。

- **触发**：八千代在分析资料，Miku 在写作，小八操作测试 App；另一宠稍后也需要前台键鼠，或两只都要写同名邀请文件。
- **输入与事实变化**：模型计算与独立 I/O 可并行。观察后据坐标/焦点执行的前台操作经同一 Host 仲裁；未获权的任务显示“等候桌面控制权”，可取消。用户手动切 App 或任务失去控制权后，下一次操作先重新观察。文件写入按实际目标和版本检查冲突，不能把前台锁误当文件一致性机制。
- **可观察结局**：三宠状态准确表示分析、等待资源、运行或待决定，人物表情不充当唯一事实。只有合法控制者发送键鼠；等待者最终可继续而不长期饥饿。对同一文件的冲突可选择重新生成/另存或按明确决定处理，不能两只都报成功却丢失内容。
- **失败与验证边界**：设计交错点击、人工接管、取消等待、控制者崩溃、两宠同文件及人工修改等变体；检查 Host 事件、焦点、文件版本和结果。任意 shell 副作用不自动受路径锁完整保护；在未覆盖相应 Tool 前不能泛称多宠并行已安全。

### UC16：断网和重启后，回到原宠物继续原任务

关联 C05、C21、C23、C30、C35、C51、C52、C53。

- **触发**：用户向 Miku 发了附图长消息，接收确认前连接断开；随后重启应用，另一只宠物还有未开始输入和一项待决定请求。
- **输入与事实变化**：草稿、材料接收状态与提交标识保持可解释；重连先按绑定身份和 Thread 恢复权威 snapshot，与已存输入对账。确认丢失不等于服务端未接收。重启后的未开始输入、已中断 Turn、未读结果和已失效请求分别呈现；继续工作由明确操作触发，不重放已发生的外部效果。
- **可观察结局**：消息没有重复、没有改投全局最新 Thread，原附件仍能访问；待决定清单指向真正所属宠。ThreadWindow 不加载或单独崩溃时，桌宠仍可创建、回复、历史恢复和答请求；宠 renderer 可以独立恢复，不连带重启健康后端。
- **失败与验证边界**：分别断在 Blob 保存前、输入持久化后确认前、Tool 副作用后终态保存前；另测离线期间目标删除和请求超时。实际测试需按服务进程、socket、存储及文件副作用分层注入故障；页面刷新保留 localStorage 或再次播放 mock 不能证明恢复正确。

### UC17：换显示器、进全屏、开安静模式仍找得到伙伴

关联 C42、C43、C54、C55、C59。

- **触发**：用户把三宠放在不同屏幕，写作时进入全屏；随后拔掉外接屏并开启安静模式，后台又同时完成两项任务。
- **输入与事实变化**：窗口按显示器工作区与 DIP 重新约束位置，失去屏幕的席位迁到可达区域；身份、Thread和草稿不变。跨 Spaces/Stage Manager 的行为遵循显式偏好，快捷键仍可召回。完成事件汇总为必要摘要，系统通知与自绘气泡分别受已定义策略管理。
- **可观察结局**：所有伙伴及其历史、停止和待决定入口都能找到；完整同屏不会悄悄变成一宠。前台打字/演示不被抢焦点，桌面不自动铺开敏感回复；关闭安静模式后未读仍可处理，没有因此取消运行。
- **失败与验证边界**：至少覆盖负坐标排列、混合缩放、Dock换边、摄像头区域、系统 Focus、全屏和恢复原显示器。透明背景不代表鼠标穿透，置顶也不保证所有空间的正确层级。必须使用实际窗口和系统证据；网页模拟显示器边框没有此证明力。

### UC18：不用鼠标和动画也能工作，语音一句话不换接收者

关联 C01、C04、C15、C17、C29、C32、C35、C56、C57。

- **触发**：用户启用 VoiceOver 与 Reduce Motion，只用键盘选择 Miku、交付资料、查旧对话并处理一项决定；另一变体使用可选按住说话。
- **输入与事实变化**：角色与控件有姓名、当前状态、操作语义和可预测焦点顺序。悬停内容可通过点击/键盘固定，拖放可由附件选择替代；读屏播报阶段和待决定，不逐 Token 打断。语音模式在录音开始时固定接收宠，持续显示对象；转写即使延迟到用户切到小八之后，也只回到原目标。
- **可观察结局**：完整核心任务不依赖精灵动画、颜色、声音、鼠标或 ThreadWindow；文字大小变化仍可读可操作。语音转写可检查，取消录音不发消息，一次只有一个明确录音目标；不愿授权麦克风的人仍可纯文字完成。
- **失败与验证边界**：实际 VoiceOver、全键盘、放大文字、高对比度和 Reduce Motion 逐条测试；静态 ARIA 属性不是通过证据。语音要覆盖权限拒绝、取消、ASR失败/延迟、隐藏宠物和断网，不能把录音转写当作默认执行授权。语音为额外能力，不作为文字主链路成立的前提。

## 记录验收时必须保留的关联

每次测试记录用户任务结局、实际触发入口、显示方式、宠物/Thread、使用的角色版本、必要工作位置、交付标识/请求关联、最终产物与失败恢复；只记录判定所需信息，避免复制真实材料或凭证。跨宠转交与重试保留同一任务关联，不能拆成多份成功记录。

每个 UC 的正常路径和异常变体分别给证据，并注明原型、协议/持久化、原生系统或真实用户试用层级。一个变体通过不覆盖同 UC 内所有分支；任何必经 ThreadWindow 或独立设置的步骤均如实进入 [完成口径](./capability-matrix.md#如何验证-99以及何时不能这样宣称)，不得通过改名窗口、减少分母或只统计最顺利的路径达标。
