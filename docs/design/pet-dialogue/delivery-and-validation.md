# 实现路线与验证关口

这是本次设计的后续实施路线，不是已完成的生产改动清单。开发时将各切片转成 GitHub spec/use case，按仓库 worktree、分层基线、完整用例、文档审核与提交流程推进；本次不对外发布 issue 或评论。

## 推荐切片顺序

| 阶段 | 交付的完整用户行为 | 涉及现有边界 | 离开该阶段的证据 |
| --- | --- | --- | --- |
| P0 身份与原生基础 | 创建/编辑三份桌宠档案；从无历史状态分别交谈；可完整同屏或单位置切换；同皮肤仍可辨认 | core protocol/Thread、ThreadPersistence、thread-store、SystemPromptSection、Electron 窗口/IPC、Swift readiness | 三个真实 Thread 的 petId、实际提示与持久快照不同且可恢复；ThreadWindow 不可用时仍能起聊；真实三宠窗口可召回 |
| P1 完整会话与控制 | drop新建/追加、每宠历史/草稿、建议/权限/Workspace、长文工具详情、停止/队列、结果带走 | pet controller、共享 store/input controller、现有 core 请求/队列与 Blob | 从接收→决定→执行→停止/恢复→成果全部经宠物完成；错投/双回执为零；取消语义不止停动画 |
| P2 所有入口与可靠性 | PromptPanel/选区/截图/AgentTrigger 归属、伙伴与角色设置、模型/模板/工具/权限管理、跨宠转交与故障恢复 | Swift Coordinator/codec、受限 bridge、共享设置 owner、宿主取消与资源仲裁 | 后台触发不抢当前；只用宠物及其附属表面完成配置和错误修复；多宠前台写操作有真实仲裁；服务/renderer分别恢复 |
| P3 规模与体验验收 | 大量历史分页/搜索、多个活跃会话、能耗/辅助技术、安静策略、真实任务研究 | 历史索引、轻量状态流、窗口调度、查询性能与观测 | 关键能力全部通过自动与原生门槛，再以真实任务口径验证99%；若未达到，继续修复实际回退原因 |

P0–P3 是依赖顺序，不意味着后面阶段可被“99%”排除。权限、Stop、无障碍、失败恢复等关键路径尚缺时，不宣布桌宠主入口完成。语音、自动长期记忆和宠物群聊不作为以上目标的必要依赖；它们的边界已在方案中留出。

## 用例驱动的实施粒度

每次实现一个跨边界用例，而不是先分别做完数据库、窗口和漂亮空界面。正式计划应写清触发、Thread/档案数据、接口契约、可见结果与必要反例，再编写整条链路的集成测试。详细场景见 [journeys.md](./journeys.md)，能力盘点与99%指标见 [capability-matrix.md](./capability-matrix.md)。

1. **档案→新对话→模型→持久恢复**：临时 SQLite、真实 Registry/Thread/路由，只替换模型与外部系统。断言实际模型请求中的角色、存储快照与恢复后的身份，不能只断言 UI 名字。
2. **A读取中切B→A完成**：真实输入控制器和存储，受控延迟文件物化；断言接收宠、Thread、opId、Blob及可见未读，目标删除则保留未发送资料。
3. **A/B并行→请求/取消→历史**：核心请求仲裁与队列保持真实；两个界面竞争回执只生效一次，Stop后队列按新规则暂停，明确继续才执行。
4. **禁用详情窗→全链路仍完成**：故意让 ThreadWindow load/crash失败，桌宠可创建、恢复、审批、读取成果；Dynamic Tool Provider不被不相关窗口故障下线。
5. **共享宿主→资源与外部结果**：受控原生 App/临时文件作为边界，两个 Thread不能同时注入前台事件，同路径写冲突不静默覆盖。

生产实现的可观测事件至少能关联 petId、threadId、opId、turnId、requestId 与窗口实例；记录必要状态和耗时即可，测试日志默认不写用户正文、API Key 或完整文件内容。界面埋点不能成为另一套运行事实。

## 原型能回答什么

| 证据层 | 可得结论 | 不能替代的结论 |
| --- | --- | --- |
| 外部官方文档/论文 | 产品先例、API定义、特定研究结果 | 本产品已经可用、普遍效率提升 |
| UI原型及浏览器操作 | 结构比较、可见路由、可点流程、草稿与模拟状态 | 真实模型、人设遵循、数据库持久化、OS拖放 |
| 独立状态原型 | 延迟投递/角色版本/重复回执等规则可被逐步检验 | core实际执行与重启恢复 |
| 隔离 Electron 原生实验 | 真正的多透明窗口、尺寸、显示/焦点属性和渲染 | 跨App命中、IME、Spaces、多屏和取消真实工具 |
| 实机完整链路 | 指定版本、机器、来源App下的流程证据 | 未覆盖来源与长期99% |
| 真人任务与纵向使用 | 成功率、回退、误投、关系感和打扰负担 | 在不同人群/任务上的无条件外推 |

本轮结果的实际证据见 [prototype-results.md](./prototype-results.md)。后续原生清单逐项记录版本、机器、显示器、输入来源、目标与结果；不能勾一个“拖放通过”概括所有 App。

## 原生优先实验

- 三个完整角色在独立位置，文本、URL、PNG、PDF分别从真实源App拖入；本体和面板都有明确目标；延迟文件promise单独验证。
- 外部编辑器持续输入时让后台完成/许可出现；再主动点宠输入中文、组合中切宠/收起/恢复，检查无误发送及焦点归还。
- 气泡展开/滚动/缩放、角色重叠/相离、拖动越界时检查透明间隙可点击与背景可选字；cursor轮询不能拖出大块隐形拦截区域。
- 两个屏幕混合缩放与负坐标、热拔、Dock换边、全屏、Spaces、Stage Manager、睡眠恢复；全部伙伴可经菜单栏/快捷键召回。
- VoiceOver、全键盘、大文本、减少动态/透明度、高对比度；历史、许可、停止、成果完整走通。
- 共享宿主的两条前台操作链、用户手动接管与远程取消；对照真实事件和产物，不只观察角色状态。

## 规模、性能与用户实验

建议在同一台测试机记录一宠/三宠、静态/动画、一个/三个流式任务、隐藏/固定多个面板的CPU/GPU/内存与唤醒；窗口数不直接等于renderer数，也不从一次快照推断长期能耗。历史样本至少包含多宠、多Workspace、1万条Thread和长对话；列表分页、搜索取消与选择恢复均需可测。

本地点击展开和切宠的起始预算为 p95 ≤150ms，接收后立即出现目标与进度反馈；模型耗时与本地入口延迟分开记录。该预算是提议，须固定硬件、刷新率、数据量后校准，尚不是当前测量结果。离屏/隐藏动画停止绘制，流式更新合并，不让每个token触发所有窗口重排。

先用6–8位目标用户做形成性任务观察：同一模型、任务、文件与延迟，比较A/B/C并交叉安排顺序；三宠同屏/单位置分别体验，同皮肤条件单独加入。记录误投、找回历史时间、停止成功、错误建议识别、遮挡和打断，而不只问“喜欢哪个”。此样本用于发现问题，不用于证明99%。

再做至少两周真实使用观察，预先冻结任务分母与失败/回退规则。分别报告完成率、pet面完成率、无ThreadWindow率、设置外跳及置信区间；不同任务类别独立看分布。只有数据满足 [指标口径](./capability-matrix.md) 后才能宣传99%，无法测量时保持“设计目标”。

## 风险排序与停止扩张条件

| 优先级 | 风险 | 处理顺序 |
| --- | --- | --- |
| 最高 | 错宠/错Thread投递、重复外部执行、共享前台争用、错误权限范围 | 先封住路由与资源边界，再增加更多角色或动画 |
| 高 | 详情窗隐性依赖、丢草稿、隐藏请求不可达、停止后队列续跑 | 用完整失败场景验证，不能仅交付 happy path |
| 中 | 多窗口遮挡、全屏/多屏不可达、辅助技术失效 | 原生试验决定布局与降级路径，保留两种显示模式 |
| 中 | 人设差异只是文案、长期打扰、历史大规模变慢 | 同任务角色预览、纵向观察、查询和渲染性能 |

新增更复杂的记忆、群聊、自主宠间协作前，应先保证上述主入口能力。否则只会增加身份与注意力负担，无法改善用户“每次请求都像在和桌宠对话”的核心体验。
