# 对话历史、输入交付与结果

## 历史入口

紧凑回复框旁保留“历史”和“新对话”两个明确入口。历史抽屉默认只列当前桌宠，显示对话标题、最近摘要、默认工作区、最后用户活动时间与状态；顶部“正在进行 / 待我决定 / 最近”是同一 Thread 索引的视图，不另造待办库。

历史按 Workspace 分组，未指定者叫“随聊”。搜索默认当前伙伴，可切“所有伙伴”；命中项显示所属宠物。打开别人的结果时整套切到那位宠物，不能由当前宠物假装说过别人的话。按宠物筛选、按 Workspace 查看所有伙伴、按对话搜索是三种可组合的查找方式。

新对话使用当前档案及其默认工作区；不按闲置超时自动建新，不因新后台 Thread 出现自动跳走。切换对话保留各自文本、附件草稿和固定面板阅读位置。悬停预览仍按既有约定每次回到底部，与固定面板的阅读位置分开。

| 历史操作 | 结果与边界 |
| --- | --- |
| 改名 / 置顶 | 只改 Thread 元数据，不重写消息 |
| 归档 | 从默认列表移出；有待决定或运行时先解释影响，默认仍在进行中视图可达 |
| 恢复 | 回到当前伙伴最近列表，不自动执行 |
| 删除 | 明示停止运行及删除历史的影响；后端完成生命周期清理后才移出 |
| 搜索全文 | 服务端分页检索消息/标题；结果锚定原 Thread 和消息，附件未 OCR 的正文不假装可搜 |
| 复制 / 导出 | 本地 Markdown/文本及可用附件链接；仅导出用户选择的范围 |
| 查看来源 | 原交付类型、来源链接、附件保存状态、转交来源；不把路径字符串当作已读正文 |

当前仅 list/resume/delete 已有协议，其余元数据、分页搜索、归档与导出需要新增，不能靠 renderer localStorage 假装持久实现。数千条历史时先取轻量列表，打开一条再取 snapshot/分页正文；不能为了未读数重建所有 runtime。

## 交付规则

保留 Issue #1 最清楚的两个 drop 目标：角色本体新建、对话面板追加。多宠只增加明确的接收宠物；单位置模式可在拖动期间通过伙伴选择器切接收者，**最终松手的高亮对象**才是目标。提前经过其他宠物不创建空 Thread。

松手时捕获接收档案、Thread（若追加）、Workspace 默认值、交付标识及 DataTransfer 内容；随后异步读文件不能改用“此刻选中的宠物”。读取期间允许用户去做其他事。目标被删除或档案被归档时保留未投递资料，显示原目标失效并让用户重新选择，不能暗中转到默认宠物。

| 内容 | 接收与读取 | 失败反馈 |
| --- | --- | --- |
| 文本 / 选区 | 保留正文与用户主动交付的来源标签 | 空白输入不提交；来源不可用仍保留已取得正文 |
| URL | 保留原链接，获取可访问正文后给依据与建议 | 登录墙、网络失败、非正文网页明确说明，不声称已看过 |
| 图片 | 先存 Blob 副本，再交给支持视觉的模型 | 不支持视觉时保留副本，说明需要选择模型 |
| PDF | 先存 Blob，解析实际文本；显示文件名与读取状态 | 加密、损坏、扫描件无文本分别说明；现有能力不保证 OCR |
| 多个文件 | 一次交付生成可见材料列表，逐项给接收结果 | 成功项保留，失败项可单独重试；不让一项失败消失整批 |
| 文件夹 / 视频 / 邮件对象 | 超出既有结构化输入支持范围 | 解释支持的形式，允许用户改交文字、链接或受支持文件 |

文件选择和粘贴提供无需拖动的等价路径。粘贴图片进入可见附件预览；确认提交前可移除。拖放的松手本身是已授权的 inspect 交付，不额外要求再点“发送”才能读取。保存失败前只显示“正在接收”，持久化确认后才说“已接收”；资料读取与模型思考是后续不同状态。

## 读完后的对话

先说明实际取得的关键内容，再给少量有区别的下一步建议。按钮的文字就是将发送的普通用户消息，可以编辑或自由回复。仅分析的 inspect 不授予执行建议的权力；保存、发送或操作应用仍按用户明确意图与 Permission 处理。

例如：八千代接住 PDF 后说“活动草案有时间和地点，缺报名方式。我可以帮你补邀请文案，或先列执行清单。” 用户点“写一版邀请文案”，形成普通用户历史；需要另一位宠物处理时选择“交给 Miku”，先看到拟交付的摘要与材料。

## 跨宠物转交

“把这一段交给…”创建目标宠物自己的新 Thread，携带用户选择的摘要、消息片段和附件引用，并显示来源。源 Thread 保留且不被换人设。转交默认 inspect，只读取材料；“请直接执行以下任务”需要用户明确填写或选定，并走正常执行授权。

正文摘要可由模型生成，但必须让用户看见其范围；长历史不会静默全部共享。跨 Workspace 转交可使用原会话 Blob 引用读取材料，不意味着把目标宠物的文件工具授权扩展到源 Workspace。复制链接或资料卡拖到另一只宠物与此流程使用同一条路由。

当前 ThreadStore 没有 Blob 引用回收合约，正式实现转交和删除时必须核对多个 Thread 的引用计数或可追溯引用集合；删除源 Thread 不得让目标已接受附件突然失效。原型只演示交接，不证明此存储能力。

## 结果可带走

最近回复提供复制；代码块、长表格与文稿在固定面板中保留格式。真实保存后显示文件名、所在 Workspace、打开/在 Finder 显示/拖出等操作，调用前校验产物仍存在。下载、生成图和文档必须有可访问的实际文件，不能只展示模拟“完成”。

把“结论”与“做了什么”分开呈现：正文为用户结果；下方轻量执行记录展示读取、调用工具、文件变化和失败节点，默认折叠，用户可展开原始参数与输出。无需打开 ThreadWindow 才能知道任务是否做完或为何失败。
