# Wisp Pocket 产品背景

<!-- impeccable:product-schema 1 -->

本文记录 Wisp Pocket 的最终产品意图与已确认的产品边界，供后续设计与开发共同使用。新决定直接替换过期表述；实现进度、代码差距与验收状态由 [对齐记录](./product-alignment.md)、规格、TODO 和 manual QA 维护。

界面现状与具体交互从 [surface 索引](./surfaces/surfaces.md) 进入；架构与规范术语分别见 [handAgent.md](../handAgent.md) 和 [CONTEXT-MAP.md](../CONTEXT-MAP.md)。

## Platform

macos

产品面向 macOS 15+ 桌面使用，结合全局快捷输入、常驻桌宠、完整对话与系统能力。Web 技术服务于桌面界面；产品范围不包含独立网站或移动端。

## 用户与任务

面向在浏览器、文档和聊天之间切换、需要 AI 协助当前工作的个人。核心任务是把正在处理的资料和近期工作线索交给 Agent，从提问继续推进到实际处理。

最优先服务的职业、技术熟练度和具体高频任务尚未确认，不默认产品专为开发者或某一职业设计。

## 产品目的与机制

**少解释背景，让 AI 接上你的工作。**

通过轻量桌面入口、用户主动交付的资料、按需环境读取与持续对话，减少重复描述背景的劳动。近期活动检索与用户配置的触发规则扩展任务起点；用户能够判断进展、交付补充资料，并在需要时作出决定。

桌宠、输入面板与完整对话界面独立接入同一个后端，各自管理导航和草稿，共享任务事实与历史。切换、收起或关闭某个界面不结束后端任务，也不切换其他界面的选择。

## 伙伴、工作区与任务

**伙伴可以重新安排，任务及历史始终留在所属工作区。**

- Pet 是前端伙伴，角色资料和桌面安排由前端管理；后端拥有 Workspace 与 Thread，Thread 只归属 Workspace。创建工作区与准备伙伴库存互相独立。
- 同一实际目录对应唯一 Workspace，项目目录固定；多个伙伴可以在同一项目工作，共享文件与项目规则，各 Thread 的模型历史独立。
- Pet 与 Workspace 各有管理入口。可见伙伴必须绑定工作区，隐藏库存可以未绑定；设置中明确选择伙伴后，可选择工作区及旧 Thread / 新对话。桌宠与工作区管理按工作区找回历史。
- 同一 Thread 最多关联一只 Pet，隐藏也计入。打开历史复用已有伙伴，无关联才分配隐藏库存；明确指定伙伴可以转移隐藏伙伴的 Thread，可见伙伴占用的 Thread 不可夺取，无论其 Turn 是否正在运行。
- 隐藏、换工作区或准备新对话不停止旧任务。同工作区召回保留原对话，跨工作区召回清空当前选择；旧任务与历史留在原项目。打开历史只恢复状态，不重放输入；新对话首次发送才创建 Thread。
- 首次使用自动准备工作区、一只可见伙伴和十几只隐藏伙伴；用户新建伙伴默认隐藏，可以先不选工作区。重启恢复用户安排，包括全部隐藏的选择，不强制显示默认伙伴。
- 桌宠仅在新对话首轮普通输入中添加角色提示。编辑角色或换伙伴接续旧 Thread 不重新注入，后端不保存伙伴身份或角色快照；后续用户要求可以改变角色表现。
- 任意入口任务的有效 Permission 请求都可复用伙伴或从库存召来伙伴承接，不主动抢焦点。无库存只提示，不夺取可见伙伴或自动创建；回执由后端仲裁一次，完整对话界面也可独立处理。
- PromptPanel 独立选择并记住 Workspace，AgentTrigger 配置目标 Workspace；ThreadWindow 按工作区管理对话，不参与伙伴分配或桌宠选择联动。
- 工作区目录失效时保留伙伴安排与历史，明确提示并阻止新一轮执行，不自动换根或项目。首版管理范围不含 Pet / Workspace 删除，Thread 删除保留。

分配与恢复的具体规则及设计理由见 [ADR 0007](./adr/0007-frontend-pet-workspace-threads.md)，单次变更的详细要求从 [规格集合](./medium-powers/medium-powers.md) 进入。

## 使用场景

- **随手提问**：通过全局快捷键唤起输入面板，选择工作区、输入请求，也可确认附带文本选区或区域截图。
- **直接从桌宠开始**：点击角色唤出并聚焦回复框，没有历史也可输入；再次点击隐藏并保留草稿，普通后台更新不解除主动隐藏。
- **交付资料并继续处理**：拖到角色开始新对话，拖到对话区追加当前对话；模型按需读取、回答或执行，建议与自由回复均可继续。常态紧凑展示最新正文与建议，悬停统一浏览完整内容，移出后仍可输入。
- **安排伙伴并接续任务**：管理伙伴资料，在工作区召来伙伴、找回旧对话或准备新对话；重新安排伙伴时后台工作继续，轻量界面与完整对话共享历史。
- **找回近期线索**：按需读取桌面环境，并查询 Context History 记录的近期应用、窗口活动与视觉证据。
- **从事件发起任务**：配置 Chrome Bookmarks 或 System Clock 规则，以预设提示词向指定工作区启动任务；书签入口依赖配套扩展与连接配置。
- **复用操作流程**：启用 Automation 后录制、保存和重跑操作流程，并查看执行历史与修复数据。
- **配置能力与偏好**：menu bar 打开独立设置，管理模型、工具、伙伴与工作区；输入面板的原生设置管理外观、Host、触发器、Append Prompt 与快捷键。模型、MCP 与伙伴资料显式保存，失败保留输入；工具开关、权限撤销与显隐为即时动作。

## 上下文、执行与数据边界

- 初始任务资料来自用户确认提交的内容；执行规则与时间基准作为内部上下文持久保存。未主动交付的屏幕、剪贴板、文件和应用状态由工具按需读取。首轮可按用户要求执行，追问按需进行，建议本身不产生执行授权。
- 新对话首个实际 Turn 请求模型前注入本地时刻与时区；后续 Turn 距最近一次已保存时间注入严格超过一小时才追加提示，整一小时不追加，连续对话和重启接续沿同一持久基准判断。小时内的提示只是最近注入时刻，不承诺实时准确，也不以消息接收时刻锚定查询。
- Context History 保存和查询结果使用本地带偏移 ISO8601、秒粒度，排序与过滤按绝对时刻。活动和缩略图查询指定时间范围时，由模型明确提供 start/end，包含端点，先过滤再按最新时间和 limit 截取；不自动把自然语言“最近十分钟”转换为相对窗口。时间注入与历史证据的发生时刻分别保留，不能把最新若干条等同于指定时间范围。
- 主 Agent 只保留问答、读取与 Codex 委托，自行判断任务复杂度；需要自主规划、多步执行或反复验证的复杂任务，以及所有写文件任务，交给 Codex CLI 执行。移除 `use_tools` 与主 Agent 的扩展执行入口。首版依赖用户事先安装并登录的 Codex CLI，沿用其模型与配置；设置展示可用状态，缺失时明确说明。
- 主 Agent 自行决定新建或接续 Codex 会话；不强制每次新建，也不强制一个 Thread 只对应一个 Codex 会话。Wisp 现有 MCP、macOS 与 Automation 能力迁到 Codex 的工作后续单独处理，本期不改这些能力的实现或提供新的接入接口。
- 文件与四个历史读取工具默认开放、免 Permission。文件读取允许任意本地路径，相对路径以所属工作区为基准。其他现有工具保留本次 / 永久决定，永久规则按完整工具名称生效；Codex 委托的授权与执行边界另待确认。
- 项目根 AGENTS.md 每个 Turn 开始读取一次，同轮固定，下一轮重读。用户明确要求优先于项目规则，项目规则优先于角色习惯；文本不改变工具权限。缺失按空规则，读取失败明确结束该轮。
- 桌宠文件交付原路径，消息显示文件名卡片；模型读取调用发生时的内容，不复制用户原文件，路径失效明确报错。不增加原文件变更监控或失效恢复。伙伴配置图片保存受管副本，PromptPanel 截图作为主动图片输入；桌宠输入范围不含截图 / 剪贴板图片。
- Context History 随应用常驻采集；权限缺失或采集失败明确显示，旧历史仍可读取。采样证据不等于完整操作日志，无记录不能直接解释为没有活动。Automation 默认关闭，独立保存启用选择；候选修复不等于重跑成功。
- 对话、资料引用、伙伴配置和采集记录保存在本机。模型请求及上下文发送给用户配置的服务，网页搜索与正文抓取访问外部网络；系统读取和操作依赖相应 macOS 权限，图片理解依赖多模态模型。
- 支持用户配置模型、MCP 与 Append Prompt；后端校验、保存并协调其所用配置的运行生效，界面不编排工具连接刷新。原生偏好独立保存，配置修改互不覆盖。

## 产品原则

1. 从用户正在做的事开始，减少为使用 AI 重新组织背景的成本。
2. 按问题取得所需上下文，保留主动交付、历史采集与执行授权的边界。
3. 让伙伴安排与任务执行独立，切换界面或伙伴仍能接续同一工作历史。
4. 明确任务进展、需要用户决定的事项与能力限制，不用动画或界面状态替代真实执行结果。

首要用户细分与高频任务排序、量化成功标准、商业模式和产品级无障碍验收标准尚未确定。个人记忆的召回与更新、Agent 归纳流程及自主修复的产品范围需要继续收敛，不据此生成效果数字或商业承诺。
