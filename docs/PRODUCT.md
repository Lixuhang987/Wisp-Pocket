# Wisp Pocket 产品背景

<!-- impeccable:product-schema 1 -->

本文是整个 Wisp Pocket 的共享产品背景，覆盖原生输入与设置、桌宠、完整对话界面和后台能力。各工程模块共同实现一个产品，不分别建立产品定位。后续产品设计先读取本文；架构与术语分别见 [handAgent.md](../handAgent.md) 和 [CONTEXT-MAP.md](../CONTEXT-MAP.md)。

界面层的任务、布局、状态与待确认事项从 [surface 索引](./surfaces/surfaces.md) 进入，各 brief 共用本文的产品背景。

本文分别记录产品目的、已确认方向和当前能力。产品方向以用户确认的后续决定为准，不能因代码尚未实现而退回旧设计；当前能力以代码及其验收证据核对。规格演进与实现状态见 [对齐记录](./product-alignment.md)。

## Platform

macos

当前产品运行于 macOS 15+，由 Swift / SwiftUI 原生界面与 Electron / React 常驻界面共同组成。Web 技术是桌面产品的实现方式，不代表已提供独立网站或移动端产品。Impeccable 当前平台枚举未覆盖 macOS；此处按实际平台记录，不套用 iOS 平台指导。

## 用户与任务

现有产品介绍面向在浏览器、文档和聊天之间切换、需要 AI 协助当前工作的个人使用场景。核心任务是把正在处理的资料和近期工作线索交给 Agent，从提问继续推进到实际处理。

最优先服务的职业、技术熟练度和具体高频任务尚未确认，不据此默认产品专为开发者或某一职业设计。

## 产品目的

**少解释背景，让 AI 接上你的工作。**

减少用户向 AI 重复描述工作背景的劳动：随手发起请求，按需取得相关上下文，在同一段对话里继续推进任务。用户能自然地交付资料、判断当前进展，并在需要时作出决定，是后续设计的判断依据；尚无已确认的量化成功指标。

## 产品机制与定位

将轻量桌面入口、用户主动交付的资料、按需环境读取和持续对话组合为同一条工作流程。桌宠与完整对话界面共享对话历史，用户可以从轻量交互进入更完整的处理过程。

桌宠、输入面板与完整对话界面独立接入同一个后端，各自管理导航和草稿；切换、收起或关闭某个界面不结束后端任务，也不切换其他界面的选择。近期活动检索与触发规则扩展任务起点，历史按需读取。以上机制不构成行业独有性或效果领先的声明。

## 已确认的下一轮产品方向（待实现）

2026-10-04 已发布 [Issue #9](https://github.com/Lixuhang987/Wisp-Pocket/issues/9)：**伙伴可以重新安排，任务及历史始终留在所属工作区。** 这是已确认的产品方向，不属于待决问题；当前代码仍采用下文 Issue #8 的模型。

- Pet 是前端伙伴，资料和桌面安排由前端保存；后端不再拥有 Pet 身份，Thread 只归属 Workspace。Pet / Workspace 各有管理入口，创建项目不再附赠基础 Pet。
- 可见伙伴必须绑定工作区；隐藏库存可以未绑定。设置中明确选择伙伴后，可以选择工作区及旧 Thread / 新对话；桌宠历史按工作区找回。首次使用准备工作区与一只可见伙伴，其余内置伙伴作为隐藏库存。
- 同一 Thread 最多关联一只 Pet，隐藏也计入。自动打开历史复用已有伙伴，无关联才分配库存；明确指定伙伴可以转移隐藏伙伴的 Thread，可见伙伴占用的 Thread 不可夺取，无论其任务是否正在执行。
- 隐藏、换工作区或准备新对话不停止旧任务；旧历史只恢复，不重放输入。同工作区召回保留原对话，跨工作区召回清空当前选择，旧任务留在原项目。
- 桌宠仅在新对话首轮普通输入中添加角色提示；编辑伙伴或换伙伴接续旧 Thread 不重新注入。该首版策略已确认，后续角色变化策略另列 TODO。
- 任意入口任务的有效 Permission 请求都可由桌宠复用伙伴或从库存承接；无库存只提示，不夺取可见伙伴。回执仍由后端仲裁一次，不主动抢焦点。
- PromptPanel 与 AgentTrigger 直接以 Workspace 为目标；ThreadWindow 保持独立，不参与桌宠分配或选择联动。首版不提供 Pet / Workspace 删除，既有 Thread 删除保留。

详细分配、恢复和验收边界见规格与 [ADR 0007](./adr/0007-frontend-pet-workspace-threads.md)。现有点击、hover、输入与显隐交互继续保留；本方向不等于已经交付新管理页或伙伴转移能力。

## 当前使用场景

- **随手提问**：通过全局快捷键唤起输入面板，输入请求，也可确认附带文本选区或区域截图。
- **直接从桌宠开始**：点击角色唤出并聚焦回复框，没有历史也可输入；首次发送才创建对话。再次点击隐藏并保留草稿，普通后台更新不解除主动隐藏；有效 Permission 请求会召回隐藏宠而不抢焦点或切选。
- **交付资料并继续处理**：向桌宠拖入文本、链接或本地图片 / PDF 路径，由模型按需读取、回答或执行；建议与自由回复均可继续。常态紧凑展示最新正文与建议，悬停统一浏览完整消息、建议及交互请求；移出后仍可继续输入。需要时在完整对话界面查看历史与推进任务。
- **找回近期线索**：请求涉及桌面环境时按需使用工具；应用运行时 Context History 持续采集，可查询已记录的近期应用与窗口活动。
- **从事件发起任务**：配置 Chrome Bookmarks 或 System Clock 触发规则，以预设提示词向指定桌宠启动任务；书签入口依赖配套扩展与连接配置。
- **复用操作流程**：启用 Automation 后录制、保存和重跑操作流程，并查看执行历史。
- **配置伙伴与项目**：menu bar 打开独立 Electron 设置，按 AI / Agent / Pets 配置模型、工具和伙伴；输入面板仍打开原生外观、Host、触发器、Append Prompt 与快捷键设置。

入口操作与本地体验步骤见 [README.md](../README.md)，真实系统行为的已验范围与待验边界见 [manual-qa.md](./manual-qa.md)。

## 当前能力与约束

- 初始上下文来自用户确认提交的内容；未主动交付的屏幕、剪贴板、文件和应用状态由工具按需读取。
- 首轮可按用户要求执行，追问按需进行。file.read 与四个历史读取工具默认开放且免 Permission；读取允许任意本地路径，相对路径基于所属 Workspace 固定文件根，内置写入仍限于该根并遵守权限策略。
- Context History 随应用常驻采集，缺失权限或采集失败在设置中明确显示，旧历史仍可读取；Automation 默认关闭并独立保存启用选择。关闭窗口不等于退出应用，已启动任务和后台能力可继续运行。
- 桌宠 PDF、图片等文件以结构化 `file_reference` 交付原路径，消息只显示文件名卡片，模型调用 file.read 时读取当前内容；不复制原文件，路径失效明确报错。PromptPanel 截图继续现有图片输入；桌宠不接收截图 / 剪贴板图片，不增加原文件变更监控或失效恢复。原因与跨模块边界见 [ADR 0004](./adr/0004-context-history-default-tools.md)。
- 对话、附件、配置和采集记录保存在本机；模型请求及其上下文会发送给用户配置的模型服务。网页搜索与正文抓取涉及外部网络服务，不将产品描述为完全离线。
- 支持用户配置模型服务、MCP 工具与 Append Prompt；系统读取和操作依赖相应 macOS 权限，图片输入依赖模型的多模态能力。
- 产品仍在开发中。个人记忆、Agent 归纳流程与完整自主修复属于后续方向，不作为已交付能力；具体待办以 [TODO.md](./TODO.md) 为准。

当前项目与伙伴边界沿 [Issue #8](https://github.com/Lixuhang987/Wisp-Pocket/issues/8)：同一实际目录唯一对应 Workspace，Pet 固定归属项目，Thread 保存双方身份与创建时角色快照；从 Pet 表单创建新项目产生基础 Pet 与用户 Pet 两只，已有项目只增加用户 Pet。项目根 AGENTS.md 每个 Turn 开始读取一次，用户明确要求优先于项目规则、项目规则优先于角色习惯；缺失按空规则，读取失败明确结束该轮。这些是当前实现边界，其中固定 Pet 归属与角色快照将在 Issue #9 中替换。

ThreadWindow 展示全部 Workspace，只按项目一级分组；新建时可指定项目内 Pet，省略则后端随机选择，重试保持同一身份。桌宠保留本宠历史与草稿；隐藏状态不影响随机候选，有效 Permission 仍可召回隐藏宠。模型、MCP、Pet 表单显式保存，失败保留输入；MCP 保存仅确认配置，运行刷新仍是后续待办。本期不新增 Workspace/Pet 删除、归档或旧开发 schema 兼容，完整实机与真实模型尚待验。

## 产品原则

1. 从用户正在做的事开始，减少为使用 AI 重新组织背景的成本。
2. 按问题取得所需上下文，保留主动交付、历史采集与执行授权的边界。
3. 让轻量入口与持续任务衔接，共享工作历史，避免让用户为切换界面重新开始。
4. 明确当前进展、需要用户决定的事项与能力限制；区分已实现、已验证和后续规划。
