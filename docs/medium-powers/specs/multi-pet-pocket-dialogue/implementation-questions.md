## 已确认设计与规格的冲突

工作树中的[默认读取与统一输入 ADR](../../../adr/0004-context-history-default-tools.md)已记录取消 inspect/reply、首轮开放工具、文件按路径交付和任意路径读取。多宠规格仍要求 inspect 预读和 rootPath 内读取，必须统一；不能将两套规则同时交付。取消分阶段本身已有设计决定，不再要求用户重复决定。

## 一次性问题清单

| 编号 | 需要决定的行为 | 推荐答案（待确认） |
| --- | --- | --- |
| Q1 | 任意路径读取后，rootPath 对读取 / 写入分别约束什么，文件读取是否需要 Permission？ | rootPath 是相对路径基准和内置写入边界；读取可指定任意路径，读取仍走既有 Permission；不复用旧受限读取工具的永久授权来默默扩大权限 |
| Q2 | 按路径交付后，原文件移动 / 删除如何处理；剪贴板、截图和浏览器提供的无本地路径内容如何交付？ | 已有文件提交原路径，失效后明确读取失败；无路径 bytes 保存为受管文件再交付其路径。保存路径不等于读取内容，已有工具读取结果保留在历史 |
| Q3 | 修改角色提示 / rootPath 是否影响旧 Thread 的下一轮？ | 保留现有规格默认：旧 Thread 冻结创建时角色和文件根，新 Thread 用新配置；名字 / 图片即时更新 |
| Q4 | 同宠旧 Thread 或隐藏宠有 Permission 请求，但用户正在其他 Thread 编辑，如何发现和处理？ | 角色显示待决定状态，伙伴 / Thread 列表显示实时待答项；用户显式选择目标 Thread 后按原点击 / hover 合约审批。无自动切选、抢焦点或阅读标记 |
| Q5 | 重启或停止后有 pending 输入，归档被 busy 拒绝，用户如何处理它们？ | 补充显式取消尚未开始输入的入口；保留原消息与取消记录，不取消运行 Turn、不增加队列暂停；重启不自动运行 |
| Q6 | 归档窗口已回收，而消息完整正文只在桌宠 hover 可读，归档历史正文在哪看？ | 归档管理入口先显示只读摘要列表；需要完整正文时显式恢复桌宠再阅读，恢复仍不自动启动旧任务 |
| Q7 | 自定义宠图片是否需要动画？ | 首版自定义宠用静态图；内置八千代继续已有动画；上传动画取首帧，不要求制作图集 |
| Q8 | 旧开发 Workspace / Thread 是否必须保留并转换？ | 保留规格默认的一次性备份和转换，无旧 API 兼容层；不直接清空已有开发历史 |
| Q9 | 完整历史和审批卡只有 hover 可见，但 M07 要求全键盘 / VoiceOver 浏览历史与审批，哪条边界优先？ | 保留用户明确的 hover 交互；本轮键盘验收只承诺历史选择和可达控件，不承诺完整正文 / 审批的全键盘操作。若要求完整可访问性，需另定键盘进入浏览的行为 |

Q1/Q2 涉及共享后端输入和 Tool 合约，最终答案必须与 ADR 0004 同步；Q3/Q7/Q8 是已写进规格但尚未由用户明确确认的默认值，其余是未闭合的流程或验收矛盾。

## 可由实现直接补齐的工程事项

- 隐藏只改展示：在途提交不能因 renderer 销毁丢失；读取 / 提交确认期间延后回收，或先移交受控接收 owner。已确认输入继续运行，未确认失败保留对应草稿 / 材料与稳定身份。
- 后端按 petId 提供实时摘要及待答状态，不能依赖仅选中 Thread 的消息订阅；完整历史仍按明确 resume 获取。请求状态不等于阅读状态。
- 同文件锁已规定按真实目标路径串行；等待锁的调用在真正写入前检查 Turn 中断，已完成的磁盘写入不能声称回滚。
- 多窗各自用绑定 petId 的配置、布局和草稿键；新宠默认显示，重启恢复可见集合，隐藏后有管理入口召回。重叠时主动操作窗口置前，不自动挪动其他宠。
- Pet 创建与首轮提交分步失败时保留同一个空 Thread 和提交身份，重试不能再创建一段历史；角色提示通过后端 system section 注入。
