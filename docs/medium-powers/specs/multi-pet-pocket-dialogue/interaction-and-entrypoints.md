# A「口袋对话」交互与入口

本文是[多桌宠规格](./multi-pet-pocket-dialogue.md)的交互验收合约；实现已落地，原生行为仍待实机验收。先读 [当前桌宠 surface](../../../surfaces/desktop-pet.md)：本规格扩展身份与 Thread 选择，保留现有点击、hover、聚焦、显隐和草稿交互；视觉继承现有主题和桌宠紧凑方案。

## 创建与管理

按 2026-10-03 用户修订，任一桌宠右键菜单中的“伙伴”入口和原生 Settings 都能打开同一批桌宠的管理功能；伙伴 / 对话 / 隐藏入口常态不展示，大小调节也从右键菜单进入。Settings 的“工作区”页直接替换为“桌宠”页；功能包括列表、添加、编辑、设为默认、显示 / 隐藏，不再出现单独 Workspace 选择。

添加表单必须能直接填写名称、角色提示、选择图片和 rootPath；内置图可选，角色提示可提供可编辑的基础文本。保存前有图片预览和 rootPath 验证反馈；取消不创建 Pet，成功后可立即显示 / 选择新宠。原始角色提示直接可编辑，不要求先拆成复杂人格字段，不增加生成图片或预览聊天功能。

编辑名字 / 图片注明不影响对话归属；编辑提示注明“仅新对话使用，已有对话保留原设定”；rootPath 创建后只读，不提供改根入口。本期不提供宠物归档 / 恢复；隐藏只影响角色可见性，不改变身份、历史或任务。

## A 的三个交互状态：保持现有 surface

| 层次 | 目标合约 |
| --- | --- |
| 常驻角色 | 完整图片；短名称 / 短 ID 与本宠入口在右键菜单中提供；必要的运行 / 待决定文字状态。首次无显隐偏好时仅角色，之后恢复逐宠对话显隐；菜单不改变点击显隐语义 |
| 紧凑对话 | 点击桌宠唤出并聚焦回复框，展示最新非空 assistant 消息及全部当前建议；沿用约 210px 列宽、44px 输入行及其下方小图标工具行和最新正文最多三行；无历史也能输入，再次点击隐藏 |
| 悬停浏览 | 仅 hover 对话区时展示当前 Thread 全部用户 / assistant 历史、完整最新消息、建议和有效请求，合用一个滚动流；回复框固定在外。移出立即回紧凑态，保留输入节点、焦点和草稿；每次进入回底，本次手动上翻后不抢回底 |

不新增固定消息面板、点击“展开”或锁定悬停的状态；聚焦本身也不展开历史。悬停只浏览当前 Thread 的消息，不等于选择其他 Thread。单宠只有一个主动编辑面，当前对话不显示身份标题气泡（含创建时名字/角色版本和原设定提示）；消息共用底部对齐的滚动内容，composer 固定在外，短内容在 hover 前后位置稳定。文件位置仍取 Thread 所属 Pet 固定目录，但当前对话不展示目录文字或路径 title，目录在伙伴管理 / Settings 中查看。角色快照仍保存并用于实际执行。工具调用沿用当前 surface，不插入桌宠消息历史；本轮不扩展详细工具过程的桌宠呈现。

管理 / Thread 选择弹层独立关闭，不增加消息面板的退出状态；消息区仍由角色点击显隐、对话区 hover 展开 / 移出收起。收起不提交、不回答权限、不停止运行或清草稿。Enter 发送、Shift+Enter 换行，IME 组合期间 Enter 只确认候选。hover、后台进度、接收完成及错误都不抢输入焦点；普通后台消息不解除用户主动隐藏，Permission 请求按下文规则显示隐藏宠。

## N 宠显示与导航

本次仅实现多宠同屏，由用户选择可见集合，各宠同时显示完整形象、独立移动 / 缩放；每宠独立保留点击显隐状态，仅被 hover 的对话区进入历史浏览。伙伴管理列表使用动态集合，可搜索名称，不写死预设角色或数量；验收必须覆盖五宠同屏。

每个可见宠使用一个绑定稳定 petId 的受控小窗口，所有窗口共用同一后端。窗口只按可见集合创建，隐藏角色时回收不用的窗口；仅隐藏对话不回收角色窗口。新宠创建成功默认显示，重启恢复可见集合；在途输入获得明确接收结果前延后窗口回收，避免提交随 renderer 消失。新宠在可用工作区内错位摆放，放不下时由用户调整位置 / 大小或可见集合，不静默丢失身份。

每宠保存 selectedThreadId，草稿按 `(petId, threadId 或 new)` 归键；导航、隐藏、位置、缩放是界面状态。草稿以本机持久偏好恢复，保存失败明确提示并保留本次内存草稿。在各宠窗口间编辑、切 Thread、隐藏和 renderer 重建不能把草稿提交为历史或串给他宠。

首次进入某宠时，有仍存在的上次主动选择就恢复它；无选择时只在本宠历史中选最近更新项，空历史显示新对话空态。后续 thread.started、旧结果和 AgentTrigger 更新只更新对应后端事实投影，只有本界面关联的主动创建确认或明确导航改变当前选择。删除 Thread 使选择无效时回本宠剩余历史或空态，不能跳到他宠全局最新项。

本宠“对话”入口打开 Thread 选择弹层，列该 petId 的分页 Thread、标题 / preview、时间和当前状态，支持选择与显式删除确认；新建对话图标放在输入框下方，只切换到 new 草稿并聚焦，不创建 Thread。选择后关闭弹层，消息区仍按点击 / hover 合约展示；弹层不承载固定的完整消息阅读面。打开结果始终显示真实归属。首版不加全文搜索、跨宠摘录发送或转交操作。

## 输入与异步接收

| 入口 | 路由与结果 |
| --- | --- |
| 空态文字 / 新话题首次发送 | 捕获 petId，创建 Thread 后提交一次首轮；先等持久 user.message.recorded 再清除对应未继续编辑的草稿；只打开空框不创建历史 |
| 角色本体 drop | 新建该宠的 Thread，提交普通 UserInput；dragover 标明宠名与“新对话”，只有最终松手提交 |
| 对话区 drop | 追加该宠当前 Thread，提交普通 UserInput；无当前 Thread 时明确提示用角色 / 新话题入口，不悄悄追加他宠 |
| 普通回复 / 建议 | 通过被编辑 Thread 的 op.submit 提交普通 UserInput，运行期间持久排队；建议不另造 Approval 语义 |

最终 drop 同步捕获 petId、new / append、目标 threadId、DataTransfer 和稳定提交身份，再异步解析可交付的文本 / 原文件路径；接收完成前转去操作另一宠、换历史、关闭窗口或隐藏都不改目的地。new 尚未创建 Thread 时，以被捕获 Pet 在服务端实际创建时的 revision 为准；角色快照仍持久保存，当前对话不显示创建时的名字与角色版本，实际文件目录从伙伴管理 / Settings 核对，不增加路径提示。

桌宠接收文本、链接及具有本地原路径的 PNG/JPEG/WebP、PDF；文件路径用现有文本 Input Item 交付，由 LLM 按需调用 file.read，不自动预读或复制用户文件。接收失败保留目的地和输入，区分未提交与后续工具读取失败；目标 Thread 已删除时明确失败，不自动转给默认宠。首轮 commandId 与 opId 可关联，ACK 不确定时先查询 / 恢复相同身份，不换 ID 盲目重发。

输入框下方的文件图标选择原路径，只加入选择开始时的 Thread/new 草稿上下文，不创建或开始 Turn；可移除文件名 chip 不显示完整路径。主动发送时文字与资料统一提交，持久 ACK 才清已提交文件，期间新增资料和新编辑文字保留；失败重试与重建保留资料。建议仍独立提交文字，不消耗待发送资料；文件上下文按宠/Thread 与文字一同保存、导航和删除。文字仍可普通粘贴。桌宠本期不接收截图、剪贴板图片或无本地路径的图片 bytes，不增加物化临时文件、复制、原文件变更监控或失效恢复。输入无 inspect/reply 分阶段，首轮可执行，user.ask 仅按需追问；file.read 免 Permission，其他工具沿既有策略。

## 请求、停止和恢复

Permission 沿用 hover 后统一滚动区中的请求卡，展示工具、参数、一次 / 永久范围、允许 / 拒绝及剩余有效时间；请求标题含所属宠与 Thread。移出仍回紧凑态，不锁定消息区；请求继续由后端持有。沿用 60 秒有效期和首次有效回执规则；已解决 / 超时通过后端通知在订阅界面移除或标为失效，不能批准旧 requestId。隐藏宠收到有效 Permission 请求时，直接重新显示到桌面，包括恢复角色窗口与紧凑对话，不抢输入焦点；仍只在 hover 后展示请求卡。保持 selectedThreadId 不变，同宠另一段 Thread 的请求不自动切选或增加特殊提醒，用户须显式选择该 Thread；不把其请求插入当前历史。这是权限请求对主动隐藏规则的明确例外。

发送按钮在当前 Thread 运行时切换为停止，经已有 Interrupt 停止其 Turn；没有独立停止按钮，停止保留草稿和文件。Enter 仍能提交运行中的补充输入；不把关闭窗口或隐藏当停止。沿用现有队列与冷恢复语义，不添加“停止全部任务 / 暂停整个队列”的承诺；运行中的后续输入仍持久排队；有排队消息时应用重启后的处理策略单列 [TODO](../../../TODO.md)，本期不新增继续 / 放弃队列协议，不自动重放已开始任务。Dynamic Tool 没有远程 cancel 的事实必须保留：停止投影不等于外部宿主动作已撤销，不宣称已经取消未收到取消证据的操作。

后端或 renderer 断连恢复以 pet.list、所选 petId 的 thread.list 和明确 thread.resume / snapshot 为准，已接收输入按稳定 opId 去重。归属 / 快照 / 未开始输入从后端恢复，草稿从本机界面状态恢复；未完成 Turn 显示中断 / 失败，不自动重试外部副作用。隐藏角色或转去另一宠窗口不关闭 Thread 运行 owner。

## 后台触发归属

AgentTrigger Instance 保存明确 targetPetId，每次事件默认新建该宠 Thread；不新增指定长期 Thread 策略。新配置必须明确选定目标宠，不转换旧开发规则；运行时目标不存在则记录可见失败，不静默改投当前宠或默认宠。后台创建 / 完成只更新目标宠，不抢用户选择或焦点。

## 原生窗口合约

Electron main 持窗口集合与 sender→窗口 / Pet 映射，IPC 操作目标从已登记 sender 解析；不信任 renderer 传任意 windowId 控制别宠。preload 保持 contextIsolation / nodeIntegration 安全边界，仅暴露图片选择、文件选择和窗口意图等窄能力。

沿现有实际 DOM 矩形更新命中，裁剪外透明空白穿透；角色移动越过阈值不触发点击显隐。位置按 petId 保存显示器关联和相对锚点，采用 DIP / workArea；边缘展开不把角色、回复框或关闭入口移出屏幕，显示器拔出后移到可达工作区。默认不以覆盖全屏透明窗口承载所有宠。

状态不只靠颜色、动画和图片；沿现有点击 / hover 交互。启动、hover 和后台事件不抢焦点；用户主动输入才激活，对话收起后的前台焦点按既有宿主边界恢复。原生验证范围见[验收](./acceptance.md)。
