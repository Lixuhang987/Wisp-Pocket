# 验收与完成门槛

本文是[多桌宠规格](./multi-pet-pocket-dialogue.md)的实现验收，全部尚待执行。用户已确认以下测试边界；本次编写 spec 不将任何场景记为实现通过。

## 主测试边界

扩展现有 pet-conversation / thread-ownership 用例：实际 PetRegistry、桌宠 controller、共享输入控制器、协议分派、ThreadRegistry / Thread、Runtime、SQLite 和 Blob。用可控模型捕获真实模型消息与发起工具调用；传输和外部 Provider 可用边界替身。用真实临时目录观察文件结果；重启验证关闭并重建 owner / 数据库，不能只清 UI store 后称为恢复。

少量 renderer 测试补充点击、悬停、固定展开和草稿的用户操作；IPC 测试证明 sender 只能操作登记窗口；Swift 用例证明目标捕获、提交回流和详情窗故障隔离。不为每层重复写一份同样的归属测试，不用内部 Map 数量、具体 helper 调用次序或动画帧作为业务成功依据。

| T13 | A 已永久允许某工具 | B 在普通回复及 inspect 中尝试调用 | 普通回复沿全局规则；inspect 仍拒绝执行，提示词不能增权 |
| T14 | B 正编辑草稿，A 后台新建 / 完成 | 收到 thread.started / 结果 / AgentTrigger | B 的选择、草稿与焦点不变；A 正确更新未读 / 状态 |
| T15 | 五宠各有 Thread 和新话题草稿 | 切宠、切 Thread、切模式、隐藏、重建 renderer | 逐宠逐 Thread 恢复，未提交草稿不进入后端历史 |
| T16 | A 的大图正在异步读取 | drop 在 A 角色后切 B / C，或 drop 在 A 的旧对话后切新历史 | new / append 始终进入最终 drop 捕获对象，只保存一次 |
| T17 | 异步接收 / 首轮 ACK 未确定 | 目标归档或删除、断连后重试同 commandId / opId | 不改投别宠，错误可见；已成功创建 / 接收的身份不重复执行 |
| T18 | 空回复框且用户首条输入 | 创建失败 / 保存失败 / 期间追加编辑 | 失败保留对应草稿；成功确认只清原输入，不擦掉新增编辑文字 |
| T19 | inspect 材料与运行中的 Turn | 拖入、后续明确回复，再提交新输入 | 材料先保存 / 读取 / 建议；执行须等明确输入；运行中输入真实持久为 pending |
| T20 | 一个有效 Permission 请求在两界面可见 | 先后分别回执，再尝试超时 requestId | 仅首个有效决定生效，两端清理，过期回执无效 |
| T21 | A Thread 执行，B 独立执行 | 在 A 按停止本轮或隐藏面板 | 中断只影响 A 当前 Turn；隐藏不停止；晚到结果不污染历史；无远程 cancel 承诺 |
| T22 | A selectedThread 被另一界面删除 | 在线收到通知或离线后重连 | 清除已删选择 / 草稿，回 A 自己的剩余历史或空态，不转向 B |
| T23 | 非默认闲置宠 / 默认宠 / 忙碌宠 | 归档、恢复、设默认与并发新建 | 闲置归档保留历史 / 文件；默认先换；忙碌拒绝；恢复同 id；始终唯一默认宠 |
| T24 | 每宠超过一页 Thread | 查询特定宠、翻页、所有宠分组与 resume | 每页归属一致、游标无重复项，snapshot 与列表身份 / revision 一致 |
| T25 | PromptPanel 打开时目标 A | 改桌面显示为 B，再提交附件与文字 | 明确冻结 A，持久接收后定位 A 的原 Thread，不强开详情窗 |
| T26 | AgentTrigger targetPetId=A | 触发且正在与 B 对话，再使 A 失效 | 有效事件归 A，不抢 B；失效目标错误可见，未改投默认宠 |
| T27 | ThreadWindow 未预热 / 加载失败 / 崩溃 | 从宠新建、回复、看历史、审批并调用在线 Dynamic Tool | 任务可完成，Provider 与后端保持健康；可选详情失败独立呈现 |
| T28 | Pet 和归属 / 快照已保存，有 pending 与未完成 Turn | 服务重启 | 所属宠、图片、角色恢复；pending 可见，未完成 Turn 标为中断 / 失败，不自动重放已开始副作用 |
| T29 | 两个不同 sender 对应不同宠窗 | 越权请求移动 / 关闭另一窗口 | main 拒绝，合法 sender 的布局操作可用且不改业务身份 |
| T30 | 旧 Workspace / null / 缺失引用 Thread 与无目标触发器 | 一次性转换、再启动、注入转换写失败 | 备份先成功、归属不丢、同根不合并；重复幂等，失败不开半转换服务 / 触发器 |
| T31 | A 常态与长回复、中文输入 | 点击、hover、固定展开、移出、Escape、IME Enter | 保留 A 尺寸 / 滚动合约；固定面不消失，草稿和焦点正确，组合确认不发送 |

## 实现次序与完成定义

1. 从主 checkout 使用仓库 worktree 脚本创建工作区；确认 CodeGraph projectPath / 索引，按所涉目录文档链阅读，在修改前完成 TypeScript 基线和 Swift build。
2. 先完成 Pet 替换、持久化 / 一次性数据转换、快照、文件工具与所有客户端协议，跑通 T01–T13 / T23–T24 / T30；不能以字段只存 renderer 交付身份能力。
3. 完成 A 方案、N 宠窗口 / 草稿 / 历史、拖放目标固定及请求入口，跑通 T14–T22 / T28–T29 / T31。
4. 接入 Settings、PromptPanel、AgentTrigger 和 ThreadWindow 故障解耦，跑通 T25–T27；全链路切片完成后才能宣称本 spec 已实现。
5. 执行 `bash ./scripts/test.sh`、`bash ./scripts/swiftw test`、`bash ./scripts/swiftw build`；Electron main / preload 完整 build，记录必要失败或环境边界。运行未验证的实机项目只标待验，不伪造通过。
6. 更新相关 owning glossary、模块文档、交叉协议引用；将已实现项目从 TODO 移到 manual QA，并附 M01–M08 的步骤 / 证据或明确待验状态。
7. 按仓库要求分发不继承上下文的独立子 agent，只审核 spec、修改目录文档链与代码一致性并更新过期文档；主 agent 确认其结论及 manual QA，再提交实现。

本轮仅完成本地文档，不触发“spec 实现完成后的独立子 agent 审核”条件；未来实现不能跳过第 7 步。
