# 验收与完成门槛

本文是[多桌宠规格](./multi-pet-pocket-dialogue.md)的验收合约。实现及自动化检查见 [合并计划](../../plans/2026-10-02-pets-default-reading.md)；M01–M07 与真实模型均待验，详细状态见 [manual QA](../../../manual-qa.md)。

## 主测试边界

扩展现有 pet-conversation / thread-ownership 用例：实际 PetRegistry、桌宠 controller、共享输入控制器、协议分派、ThreadRegistry / Thread、Runtime、SQLite 和 Blob。用可控模型捕获真实模型消息与发起工具调用；传输和外部 Provider 可用边界替身。用真实临时目录观察文件结果；重启验证关闭并重建 owner / 数据库，不能只清 UI store 后称为恢复。

少量 renderer 测试补充点击唤出 / 聚焦、常态最新消息、hover 全部当前 Thread 历史、移出收起、Thread 选择弹层和草稿操作，保留现有 surface 的行为断言；IPC 测试证明 sender 只能操作登记窗口；Settings 用例验证配置读写仍经同一后端入口。不为每层重复写一份同样的归属测试，不用内部 Map 数量、具体 helper 调用次序或动画帧作为业务成功依据。

## 自动化 Given / When / Then

| 编号 | Given（前提） | When（动作） | Then（可观察结果） |
| --- | --- | --- | --- |
| T01 | 空安装 | 查询 Pet 并打开默认宠回复框 | 恰有一默认宠，含图片 / 提示 / rootPath；打开空框没有 Thread |
| T02 | 已有默认宠 | 连续创建到五只，再创建同名同图同 rootPath 的另一只 | 全部有不同稳定 id，均可列出 / 选择，没有三个角色硬上限 |
| T03 | 本地静态图 | 成功创建后删除源图，再重建服务与 renderer | 仍显示导入副本，Pet 与历史不变 |
| T04 | 无效图、超限图或无效目录 | 创建 / 编辑 | 明确校验失败，原表单与旧配置保留，无可见半成品 |
| T05 | 两界面读取同 revision | 依次编辑同宠 | 第一成功，第二 conflict 且返回当前版本，后者未覆盖前者 |
| T06 | A / B 共用 rootPath 且角色不同 | 分别首次文字与跟进，各再创建另一 Thread | Thread 按 petId 分组；模型消息有对应角色、只含该 Thread 历史；同根不合并对话 |
| T07 | Pet 角色 v1、固定文件根 R1 的旧 Thread | 编辑为角色 v2，尝试修改 rootPath，继续旧 Thread 并新建 Thread | 旧 Thread 用角色 v1，新 Thread 用 v2；改根请求被拒绝且两者仍用 R1；名字 / 图片更新不重建历史 |
| T08 | v1 Thread 已有运行结果 | 重启、resume、中断后继续 | 模型请求使用保存的角色快照，文件产物留在所属 Pet 的固定根，恢复不依赖当前角色文本 |
| T09 | 任意客户端 | 用不存在 petId 新建，或提交任意客户端快照 | 明确拒绝非法归属；有效新建的快照由服务端生成 |
| T10 | A / B 有不同文件根 | A 调用文件工具，尝试另传旧 workspaceId 或其他宠参数 | 非法归属参数拒绝；正常相对路径从 A Thread 所属 Pet 的固定目录解析；读取允许任意绝对路径，写入仍受 A 文件根约束 |
| T11 | A 文件根与已允许 file.write | 提交绝对路径、越界相对路径或越界 symlink | 无越界写入；永久 Permission 不绕过写入边界 |
| T12 | A / B 共用文件根 | A 写入、B 显式读取，再在受控顺序下写同一真实文件 | B 读到共享文件；同路径写入串行且后写按覆盖规则生效，不产生截断内容；聊天仍隔离 |
| T13 | 无任何文件读取授权，另有 A 永久允许的写入工具 | B 首轮调用 file.read，再调用需审批的工具 | file.read 默认可用且无 Permission 请求，读取指定路径当前内容；其他工具按全局规则；无输入阶段限制 |
| T14 | B 正编辑草稿，A 后台新建 / 完成 | 收到 thread.started / 结果 / AgentTrigger | B 的选择、草稿与焦点不变；A 正确更新运行 / 待决定状态 |
| T15 | 五宠各有 Thread 和新话题草稿 | 在五宠窗口间编辑、切 Thread、隐藏、重建 renderer | 逐宠逐 Thread 恢复文字与文件上下文，选文件不提交，发送统一交付并等持久 ACK 清理，失败保留，未提交草稿不进入后端历史 |
| T16 | A 的原文件路径正在异步接收 | drop 在 A 角色后操作 B / C 窗口或隐藏 A，另测 A 旧对话 drop 后切新历史 | new / append 始终进入松手目标，只接收一次；隐藏不丢在途提交，未确认失败保留输入 |
| T17 | 异步接收 / 首轮 ACK 未确定 | 目标 Thread 删除、断连后重试同 commandId / opId | 不改投别宠，错误可见；已成功创建 / 接收的身份不重复执行 |
| T18 | 空回复框且用户首条输入 | 创建失败 / 保存失败 / 期间追加编辑 | 失败保留对应草稿；成功确认只清原输入，不擦掉新增编辑文字 |
| T19 | 原文件及运行中的 Turn | 拖入路径、让模型读取后修改或删除原文件并再次读取，再提交新输入 | 输入以 `file_reference` 保存原路径元数据、无预读 / 副本；pending/live/恢复只显示文件名卡片，模型收到路径文字；工具读取当前内容，失效如实失败，无额外恢复；运行中输入持久为 pending |
| T20 | 一个有效 Permission 请求在两界面可见 | 先后分别回执，再尝试超时 requestId | 仅首个有效决定生效，两端清理，过期回执无效 |
| T21 | A Thread 执行，B 独立执行 | 在 A 点击由发送切换的停止按钮或隐藏面板 | 中断只影响 A 当前 Turn；隐藏不停止；晚到结果不污染历史；无远程 cancel 承诺 |
| T22 | A selectedThread 被另一界面删除 | 在线收到通知或离线后重连 | 清除已删选择 / 草稿，回 A 自己的剩余历史或空态，不转向 B |
| T23 | A 隐藏，A 有当前 Thread 和另一段 Thread；B 正编辑草稿 | A 任一 Thread 收到有效 Permission 请求，之后显式选择另一段 Thread | A 重新显示到桌面且不抢焦点，A 的选择不自动改变；其他 Thread 的请求只在用户选择后呈现，B 草稿不变；始终唯一默认宠 |
| T24 | 每宠超过一页 Thread | 查询特定宠、翻页、所有宠分组与 resume | 每页归属一致、游标无重复项，snapshot 与列表身份 / revision 一致 |
| T25 | AgentTrigger targetPetId=A | 触发且正在与 B 对话，再使 A 失效 | 有效事件归 A，不抢 B；失效目标错误可见，未改投默认宠 |
| T26 | Pet 和归属 / 快照已保存，有未完成 Turn | 服务重启 | 所属宠、图片、角色恢复；未完成 Turn 标为中断 / 失败，不自动重放已开始副作用；排队消息重启策略另列 TODO |
| T27 | 两个不同 sender 对应不同宠窗 | 越权请求移动 / 关闭另一窗口 | main 拒绝，合法 sender 的布局操作可用且不改业务身份 |
| T28 | A 有当前 Thread、长回复与草稿，另有一段旧 Thread | 点击角色、hover / 移出、从右键菜单选择旧 Thread、再次点击，另测 IME Enter | 管理入口常态隐藏，右键菜单动作可用；点击唤出并聚焦，常态展示最新非空 assistant 正文与当前建议，当前对话无目录文字 / 路径 title；hover 展示当前 Thread 全部消息，消息统一底部对齐，输入和工具行固定，身份标题气泡不显示，短内容 / 角色 / 回复框稳定；移出收起且可继续输入，选旧 Thread 仍沿该合约，再点隐藏；无固定消息面板，组合确认不发送 |

| M04 | 各屏四角、混合缩放和负坐标排列、热拔屏幕；Spaces / 全屏 | 角色、回复和退出 / 召回入口可达；透明空白和裁剪外区域可操作底层 App，无异常窗口覆盖 |

| M07 | 同根两宠保存和读取真实临时文稿；确认文件根不可编辑后恢复旧对话 | 产物位置遵守所属 Pet 的固定文件根，在伙伴管理 / Settings 中可核对；当前对话不展示目录文字或路径 title；同根共享文件但历史隔离，不报告不存在的成果 |

自动化模拟模型证明身份、编排、上下文与文件规则；模型对真实资料的理解、跨 App drop、透明命中、焦点与多屏必须按实机证据判断，不能用原型截图或测试项数量代替。

## 实现次序与完成定义

1. 从主 checkout 使用仓库 worktree 脚本创建工作区；确认 CodeGraph projectPath / 索引，按所涉目录文档链阅读，并先核对对应 surface 的现有交互合约，在修改前完成 TypeScript 基线和 Swift build。
2. 先完成 Pet 替换、持久化 / 破坏性 schema 替换、快照、文件工具与所有客户端协议，跑通 T01–T13 / T24；不能以字段只存 renderer 交付身份能力。
3. 完成 A 方案、N 宠窗口 / 草稿 / 历史、拖放目标固定及请求入口，跑通 T14–T23 / T26–T28。
4. 接入 Settings 配置管理与 AgentTrigger 目标归属，跑通 T25；验收只覆盖本次桌宠体验与共享后端合约，不添加其他前端的界面、导航或故障改造。
5. 执行 `bash ./scripts/test.sh`、`bash ./scripts/swiftw test`、`bash ./scripts/swiftw build`；Electron main / preload 完整 build，记录必要失败或环境边界。运行未验证的实机项目只标待验，不伪造通过。
6. 更新相关 owning glossary、模块文档、交叉协议引用；将已实现项目从 TODO 移到 manual QA，并附 M01–M07 的步骤 / 证据或明确待验状态。
7. 按仓库要求分发不继承上下文的独立子 agent，只审核 spec、修改目录文档链与代码一致性并更新过期文档；主 agent 确认其结论及 manual QA，再提交实现。

本次实现须完成第 7 步独立文档审核；自动化通过不替代 M01–M07 实机证据。
