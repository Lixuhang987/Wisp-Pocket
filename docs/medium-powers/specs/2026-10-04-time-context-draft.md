# 时间上下文与 Context History 时间查询（讨论草案）

状态：用户已提出改动方向；以下推荐语义待本轮访谈确认，尚未实现，不作为当前架构事实或已完成验收。

## 已明确方向

- Context History 的工具证据时间采用本地时间表达。
- 新 Thread 注入时间上下文；后续 Turn 发送前比较时间，超过一小时追加时间流逝提示。
- 历史查询增加按时间过滤的参数。

当前边界见 [Conversation Runtime](../../../packages/core/CONTEXT.md)、[Host Automation](../../../apps/host-automation/CONTEXT.md) 与 [根架构](../../../handAgent.md)。

## 已核对的缺口

- 2026-10-04 17:11 的真实请求没有当前时间或时区；模型调用最近 20 条活动，其中 6 条早于用户消息前十分钟，并把 UTC 的 09 时直接写作本地活动时间。
- 活动索引只有 limit，截图缩略图已有 start/end。补时间提示不会自动补齐活动查询边界。
- 一小时才更新时间意味着模型看到的“现在”可能落后近一小时，无法据此正确计算分钟级窗口。
- 当前 system section 不进入持久历史；仅增加内存计时器无法在进程重建后恢复注入基准。
- 普通 system 历史消息会进入当前历史计数，影响自动标题的首条输入判断；新增内部上下文必须一起校正这些投影。
- 当前前端会把透传的 system 历史渲染为 error；内部时间上下文应由后端可见消息投影排除，不能只隐藏某一个前端。
- 历史是采样证据；查询无记录、工具结果被截断和采集空档不能被解释为用户没有活动。

## 推荐方案与待确认选择

### 1. 本地时间的含义

推荐采用带偏移的 ISO8601，例如 `2026-10-04T17:11:57+08:00`；保留同一绝对时刻，禁止存无时区的 `17:11:57` 或给 UTC 字符串直接改标签。保存采集当时的时区信息，避免机器换时区后重写旧记录时改变“当时本地”的表达。

本期范围为 Context History 活动、截图及工具证据时间；Thread 审计和网络日志的存储格式不由此整体改写。排序、比较和过滤使用解析后的绝对时刻。自然日查询使用本轮用户时区，不能仅按 timestamp 的日期文本筛选。

### 2. 一小时刷新与分钟级准确性

推荐保留一小时规则，并给活动索引和截图缩略图提供相对窗口参数，例如 `last_seconds: 600`，由后端结合本轮可信时间基准解析。工具同时返回实际窗口与时区；绝对 start/end 继续可用，绝对与相对参数不能混用。

对于询问当前时刻或需要精确构造绝对范围的任务，推荐同时提供轻量时钟工具；一小时提示中的时间明确是上下文基准，不承诺在整小时内始终等于实时“现在”。

一小时阈值比较当前 Turn 与最近一次已持久化注入的时刻，不比较相邻 Turn；否则连续每十分钟聊天会永久不刷新。跨日、时区变化、时钟回拨立即刷新。仅在新 Turn 开始触发，不运行后台提示计时器。

注入内容包含当前带偏移时间、时区、上一基准及实际经过时间；它是内部运行上下文，恢复后仍可供模型读取，不作为新用户输入、标题来源、未处理输入或普通气泡。

### 3. “最近”的时间基准

推荐锚定后端接收该条 UserInput 的时刻，并单独保留 Turn 开始时间。同一 Turn 的活动、AX 和截图检索使用同一窗口；排队或工具耗时不能悄悄移动窗口。

需要用户决定的三项：本地时间是否采用采集时的带偏移表示；是否保留一小时提示并由工具解析相对窗口；相对窗口是否锚定消息接收时刻而非开始执行或工具调用时刻。用户可一次确认全部推荐，也可明确替代选择。

## 实现和验证边界

- 时间上下文基准必须随 Thread 持久化，恢复时读取，摘要或后续压缩不能使其失去可见的当前基准。
- 首轮应在实际 Turn 执行前生成时间上下文；仅创建空 Thread 不提前冻结“现在”。持久化、失败重试、中断、重复输入和并发入队不能形成重复注入或丢失基准。
- 时间过滤先于倒序排列和 limit；保留现有含端点语义，验证 start/end 次序、显式时区和 epoch 秒单位；明确返回匹配数量与是否截断。
- 样本详情与截图原图按 ID 读取，保持 ID 语义；时间范围参数属于集合查询工具。
- Swift 写入、Node 读取和模型工具结果必须同步；旧 Z 与新偏移时间能表示同一时刻，不增加开发期 schema 兼容工程，也不重写用户真实数据作为测试。
- Foundation 当前 ISO8601 decoder 不接受带小数秒的偏移格式；新格式继续采用秒粒度，或同步更换编码与解码策略，不能只改输出 formatter。
- 验证新 Thread、小时内/小时后、连续活跃对话、跨日/换时区/时钟回拨、进程重建、失败/中断、排队消息、过滤边界、混合偏移排序和截断提示。
- 实施前按仓库流程建立 worktree 并跑基线；完成后同步 owning 文档、manual QA，独立文档审核与三项提交前检查均完成后提交。

本草案不扩大为采集故障监控、填补历史空档或完整操作日志；已有空档必须在回答证据范围中如实表述。
