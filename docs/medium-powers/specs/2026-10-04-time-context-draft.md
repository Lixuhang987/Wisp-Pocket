# 系统提示、时间上下文与历史时间过滤

状态：2026-10-04 简版已实现，三项检查通过，独立文档审核已完成；实现与检查记录见 [实施计划](../plans/2026-10-04-time-context.md)。当前架构事实由 owning 模块文档说明，真实宿主与模型验收见 [manual QA](../../manual-qa.md)。

## 需求与因果

2026-10-04 17:11 的真实请求没有当前时间或时区；模型将最近 20 条记录当作最近十分钟，其中 6 条超出范围，并将 UTC 09 时直接写成活动时间。修复前 system 提示仅临时组成模型请求、没有进入 Thread 历史，导致恢复缺少实际提示版本及最近时间基准。该缺陷已与时间上下文一并修复。

## 已确认的第一版

- Context History 活动和截图落盘采用宿主本地带偏移 ISO8601，秒粒度；Node 工具结果也转换为后端本地时间。排序和过滤仍按绝对时刻，旧 Z 证据能自然读取，不迁移或清理用户数据。
- 新 Thread 的首个实际 Turn 执行前注入本地时刻和 IANA 时区，避免创建空 Thread 时提前冻结时间。
- 后续 Turn 开始时，只比较当前开始时刻与最近一次持久化时间注入；严格超过 3600 秒才追加时间流逝提示。整一小时不追加，连续活跃对话也以最近注入为基准。
- 本期不增加跨日、时区改变或时钟回拨的额外刷新条件，不增加后台计时器、轻量时钟工具或相对窗口参数。
- 时间上下文与工具策略、项目 AGENTS.md、角色 system 提示均进入 Thread 持久历史；模型请求之前完成落盘，失败、中断和进程恢复不丢弃已经确认写入的上下文。
- 各 system section 保留变更版本，模型仅应用各 section 最新有效内容；规则清除时保存空版本，使旧项目规则失效。重复内容不在每个工具循环或每轮重复保存。角色仍来自现行 Thread 创建时快照，配置修改只影响新 Thread；项目规则仍逐 Turn 重读，不提前实施 Issue #9 的角色目标方案。
- system 是内部上下文，不构成 UserInput，不生成普通气泡，不作为标题来源，不计入用户可见 messageCount，也不派生为 pending 输入。
- 活动索引增加 start/end，缩略图沿用相同格式：带偏移 ISO8601 或 epoch 秒，含端点，反向范围失败；先过滤，再倒序排列和 limit。样本详情及原图仍按 ID 读取。

## 数据与所有权

Conversation Runtime 拥有 Thread 内部历史及时间基准；Runtime 解析本轮 system 更新，由 Thread 经 storage 回调先持久化。持久化 adapter 与 SQLite 保存完整 system response item，不新建另一套历史或修改数据库 schema。

模型投影和用户可见投影具有不同用途：模型采用最新系统规则及已保存时间上下文，用户可见消息排除内部 system；完整内部版本仍保留用于恢复和核对。生成增量不能重复保存已先行确认的 system。

Swift Context History 写入和 Node 普通工具读取共同拥有时间证据合约，见 [Swift 存储合约](../../../apps/host-automation/Sources/sources.md) 和 [Node 读取合约](../../../apps/agent-server/src/actions/actions.md)。本期本地时间按写入/查询所在宿主时区表达，不增加采集时区历史管理。

## 验收

1. 首轮实际模型收到的规则和时间上下文可在持久历史核对；系统消息保存失败时模型不能先运行。
2. 一小时内及整一小时不重复时间注入，超过一小时追加；连续多轮及进程重建沿最近已保存基准判断。
3. 模型失败或在 system 写入期间中断后接续，已保存上下文保留且不重复；标题、消息数量、快照和排队输入语义保持。
4. 项目规则更新或删除时，最新规则生效或失效，旧版本仅留在内部历史。
5. 本地带偏移证据可落盘、重建读回；ISO8601/epoch 秒范围边界一致，过滤先于截断，活动与截图关联不变。

## 明确限制

小时内的时间提示是最近一次注入的基准，不能保证分钟级实时准确；模型显式传入查询范围，本期不自动解释“最近十分钟”。现有 limit 默认 20、最多 200，不增加分页或截断元数据。Context History 是采样证据，不保证填补采集空档或证明完整操作过程。

本期不整体更改 Thread 审计、网络日志或 Automation 的时间格式，不为未来全历史 compact 新增实现；后续压缩必须保留可恢复的时间和当前规则基准。
